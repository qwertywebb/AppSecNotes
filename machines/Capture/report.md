# Отчет по результатам пентеста машины Capture

## Введение

В ходе выполнения задания была проведена атака на веб-приложение компании SecureSolaCoders. Разработчики внедрили **CAPTCHA** для защиты от брутфорса, однако система осталась уязвимой к атакам перебора за счет различий в ответах сервера на валидные и невалидные учетные записи. Целью работы было получение доступа к панели управления (`/dashboard.php`) через подбор учетных данных пользователя `natalie`.

## Этап 2: Анализ страницы логина

### Обнаружение капчи

При неверном вводе логина или пароля сервер возвращал страницу с CAPTCHA:

```html
<h2>Too many bad login attempts!</h2>
<label>Captcha enabled</label>
<p>468 * 23 = ?</p>
<input type="text" name="captcha">
```

**Особенности реализации:**
- Капча представляет собой простое математическое выражение с двумя числами и оператором (`+`, `-`, `*`, `/`)
- После решения капчи запрос обрабатывался сервером


### Определение валидных пользователей

В ходе анализа ответов сервера была обнаружена **информационная утечка**:

| Сценарий | Ответ сервера |
| :--- | :--- |
| Невалидный пользователь | `User does not exist` |
| Валидный пользователь, неверный пароль | `Invalid password` |


## Этап 3: Разработка скрипта для брутфорса

### Архитектура скрипта

Скрипт был реализован на Python с использованием библиотек `requests`, `re` и `BeautifulSoup`.

**Основные функции:**

#### 1. `login(username)`

- Отправляет POST-запрос на `/login` с логином и паролем (по умолчанию `test`)
- Анализирует ответ на наличие ошибок
- Если сервер вернул капчу — вызывает функцию `verify_captcha()`

#### 2. `verify_captcha(response_text, username)`

- Проверяет наличие строки `Captcha enabled` в ответе
- При обнаружении вызывает `resolve_captcha()`
- Повторно отправляет запрос с решенной капчей

#### 3. `resolve_captcha(html, username)`

- Парсит математическое выражение с помощью регулярного выражения:
  ```python
  pattern = r'(\d+)\s*([+\-*/])\s*(\d+)\s*=\s*\?'
  ```
- Извлекает два числа и оператор
- Вычисляет результат и возвращает его как строку

#### 4. `get_error_message(html, username)`

- Извлекает текст ошибки из тега `<p class="error">` через BeautifulSoup
- Если ошибка содержит `invalid password` — фиксирует валидный логин


### Логика работы скрипта

```
┌──────────────────────────────────────────────────────┐
│ 1. Чтение файла с именами пользователей (wordlist)   │
│ 2. Для каждого имени выполняется login(username)      │
│ 3. Анализ ошибки:                                    │
│    - "User does not exist" → игнорируем              │
│    - "Invalid password" → логин валидный             │
│ 4. При обнаружении капчи:                            │
│    - Парсим выражение                                │
│    - Вычисляем результат                             │
│    - Повторяем запрос с капчей                       │
│ 5. Сохраняем найденные логины в список               │
└──────────────────────────────────────────────────────┘
```

## Выводы и рекомендации

### Критические уязвимости, обнаруженные в ходе тестирования:

1. **Информационная утечка при аутентификации** — сервер возвращал разные сообщения для валидного и невалидного пользователя, что позволило провести перебор имен.

2. **Некорректная реализация капчи** — математическая капча легко обходится автоматизированным скриптом, так как выражение передается в виде текста без обфускации.

3. **Отсутствие ограничения по числу попыток входа** — несмотря на внедрение капчи, система не блокировала IP-адреса при множественных неудачных попытках, что позволило провести брутфорс.

4. **Слабый пароль пользователя** — пароль `sk8board` относится к категории легко подбираемых.

### Рекомендации по устранению:

1. **Унифицировать сообщения об ошибках** — использовать общее сообщение типа `Invalid credentials` для всех случаев.

2. **Усилить капчу** — использовать современные решения (Google reCAPTCHA, hCaptcha) или генерировать изображения с текстом вместо простых математических выражений.

3. **Внедрить механизмы защиты от брутфорса**:
   - Ограничение числа попыток входа с одного IP
   - Экспоненциальная задержка между попытками
   - Временная блокировка аккаунта после N неудачных попыток

4. **Усилить политику паролей** — требовать сложные пароли (минимум 8 символов, буквы разных регистров, цифры, спецсимволы).

5. **Внедрить двухфакторную аутентификацию (2FA)** для критических учетных записей.
