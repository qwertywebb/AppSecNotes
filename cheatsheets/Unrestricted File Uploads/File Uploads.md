##  **Unrestricted File Upload (Загрузка файлов)**


### 1. Определение 

> **Unrestricted File Upload** — это уязвимость, при которой злоумышленник может загрузить на сервер вредоносный файл (например, PHP, ASP, JSP, EXE, скрипт или шелл) через форму загрузки. Если сервер не проверяет содержимое файла и его тип, злоумышленник может выполнить загруженный файл и получить доступ к системе (RCE).


### 2. Как работает атака

1. Злоумышленник находит форму загрузки файлов (аватарка, документы, вложения).
2. Загружает файл с вредоносным содержимым (например, `shell.php`).
3. Сервер сохраняет файл в доступной директории (например, `/uploads/`).
4. Злоумышленник обращается к файлу по URL и выполняет его.
5. В результате получает шелл или доступ к серверу.


### 3. Основные типы атак

| Тип | Суть | Пример |
| :--- | :--- | :--- |
| **PHP-шелли** | Загрузка PHP-файла с командой `system($_GET['cmd'])`. | `shell.php` |
| **ASP/JSP** | Загрузка скрипта для Windows/Linux серверов. | `shell.asp` |
| **Double Extension** | Обход проверки через двойное расширение. | `shell.php.jpg` |
| **Null Byte Injection** | Обрезка строки через `%00`. | `shell.php%00.jpg` |
| **Content-Type Bypass** | Подделка MIME-типа (например, `image/jpeg` вместо `text/php`). | `Content-Type: image/jpeg` |
| **Magic Bytes** | Добавление сигнатуры картинки в начало файла. | `GIF89a<?php system($_GET['cmd']); ?>` |
| **SVG XSS** | Загрузка SVG с внедренным JS-кодом. | `<svg><script>alert(1)</script></svg>` |


### 4. Методы защиты

| Метод | Описание |
| :--- | :--- |
| **Белый список расширений** | Разрешать только нужные расширения (`.jpg`, `.png`, `.pdf`). |
| **Проверка MIME-типа** | Проверять реальный MIME-тип (например, `image/jpeg`), а не полагаться на `Content-Type` от клиента. |
| **Проверка содержимого (Magic Bytes)** | Проверять сигнатуру файла (первые байты). Изображение должно начинаться с `FF D8` (JPEG) или `89 50 4E 47` (PNG). |
| **Ограничение размера файла** | Защита от DoS (загрузка огромных файлов). |
| **Переименование файла** | Сохранять файл с случайным именем (UUID) вместо оригинального. |
| **Хранение вне веб-корня** | Хранить загруженные файлы вне директории, доступной из браузера. |
| **Отключить выполнение скриптов в папке загрузок** | В Nginx/Apache отключить `ExecCGI` в директории `/uploads/`. |
| **Антивирусная проверка** | Сканировать загруженные файлы антивирусом. |


### 5. Примеры обхода защиты

| Защита | Обход |
| :--- | :--- |
| Проверка расширения (`jpg`, `png`) | Двойное расширение: `shell.php.jpg` |
| Проверка MIME-типа | Подмена `Content-Type: image/jpeg` |
| Проверка магических байт | Добавление `GIF89a` в начало PHP-файла |
| Проверка до первой точки | `shell.php.jpg` → проверяет `.jpg` |
| Null Byte Injection | `shell.php%00.jpg` (старые версии) |


### 6. Эталонный ответ

*«Уязвимость загрузки файлов возникает, когда сервер не проверяет содержимое загружаемого файла. Злоумышленник может загрузить PHP-шелли и получить доступ к серверу. Основная защита — белый список расширений, проверка MIME-типа и содержимого (magic bytes), а также хранение файлов вне веб-корня. Важно переименовывать файлы в случайные имена и запрещать выполнение скриптов в папке загрузок».*


### 7. Каверзные вопросы

**Q:** *«Как обойти проверку на расширение `jpg`?»*  
**A:** *«Двойное расширение (`shell.php.jpg`) или Null Byte (`shell.php%00.jpg`) в старых версиях PHP».*

**Q:** *«Что такое Magic Bytes?»*  
**A:** *«Уникальные сигнатуры в начале файла. Например, JPEG начинается с `FF D8 FF E0`, а PNG — с `89 50 4E 47`. Сервер может проверять их для подтверждения типа».*

**Q:** *«Как защититься от загрузки PHP-файлов в папку `/uploads/`?»*  
**A:** *«В конфигурации Nginx/Apache отключить выполнение PHP-скриптов в этой папке через `.htaccess` или `location` директиву».*


### 8. Дополнительные риски (Кроме RCE)

- **XSS через SVG** — загрузка SVG с вредоносным JS.
- **Path Traversal** — загрузка файла в произвольную папку (например, `../../config.php`).
- **DoS** — загрузка огромных файлов, заполнение диска.
