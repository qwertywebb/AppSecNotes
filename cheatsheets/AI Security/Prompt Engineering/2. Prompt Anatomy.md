# Prompt Engineering: 4 Pillars

## 1. Что такое хороший промпт?

Хороший промпт — это **структурированная инструкция**, которая чётко говорит модели:
- **Что** сделать.
- **Как** сделать.
- **Какие ограничения** соблюдать.

Промпт-инженеры часто разбивают запрос на 4 компонента (pillars).


## 2. Четыре Pillars эффективного промпта

### Instruction (Инструкция / Задача)
Это **главная команда** — что именно вы хотите получить.

**Правило:** Используйте чёткие глаголы.
- Плохо: *"Помоги с маркетингом"*.
- Хорошо: *"Напиши пост для соцсетей на 300 слов о новом экологичном продукте для миллениалов"*.


### Context (Контекст / Бэкграунд)
Это **информация**, которая даёт модели понимание ситуации: кто аудитория, какие данные есть, какая роль у модели.

**Примеры:**
- *"Ты — опытный морской биолог, специализирующийся на рыбах"*.
- *"Основываясь на приложенном отчёте..."*.

**Зачем:** Меньше догадок → меньше ошибок.


### Output Format (Формат вывода)
Это **структура** ответа: список, таблица, JSON, код, количество слов.

**Примеры:**
- *"Дай ответ в виде 3 пунктов маркированного списка, каждый пункт до 50 слов"*.
- *"Верни JSON с полями name, age, city"*.


### Constraints (Ограничения / Границы)
Это **правила**, которых модель должна придерживаться: запрет тем, стиль, обязательные элементы.

**Пример:**
- *"Напиши академический отчёт по IoT-устройствам. Цитаты в формате MLA. В конце — резюме из 5 пунктов (не больше)"*.


## 3. Золотое правило: Specificity vs Verbosity

| Тип | Пример | Проблема |
|-----|--------|----------|
| **Слишком размыто (Vague)** | *"Напиши функцию для работы с данными пользователя"* | Модель не знает, что значит "работать". |
| **Слишком многословно (Verbose)** | *"Напиши функцию, которая берёт данные пользователя (может объект или массив)… и валидируй, но я не знаю какие ошибки, просто чтобы работала и была быстрая и..."* | Модель теряет суть, игнорирует часть инструкций. |
| **Золотая середина (Just Right)** | *"Напиши JS-функцию, которая: (1) принимает объект пользователя (name, email, age); (2) проверяет email на корректность; (3) возвращает объект или выбрасывает ошибку со списком нарушений"* | Чётко описаны вход, логика и выход. |


## 4. Вывод

Промпт-инжиниринг — это не магия. Это умение давать модели **структуру вместо эмоций**. Если вы применяете 4 pillars (инструкция, контекст, формат, ограничения), вы получаете предсказуемые результаты.
