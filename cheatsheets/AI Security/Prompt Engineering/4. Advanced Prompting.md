# Продвинутые техники промптинга для безопасности

## 1. The Shot Spectrum (Спектр "выстрелов")

**"Shot"** — это количество примеров, которые ты даёшь модели внутри промпта.

| Тип | Количество примеров | Когда использовать | Пример |
| :--- | :--- | :--- | :--- |
| **Zero-shot** | 0 | Простые задачи, где инструкция понятна без пояснений | `"Классифицируй этот лог как INFO, WARN или ERROR"` |
| **One-shot** | 1 | Нужно показать формат ответа | `"Пример: SQLi в login.php → {"type":"SQLi", "file":"login.php"}"` |
| **Few-shot** | 2–5 | Сложные паттерны, несколько кейсов | `"Вот 3 примера классификации событий аутентификации (NORMAL/SUSPICIOUS/ATTACK)"` |

**Суть:** Модель учится на примерах прямо в промпте (in-context learning) — это не требует дообучения.


### Zero-shot
- **Что это:** Просто даёшь задачу. Модель сама понимает, что делать, на основе знаний из тренировочных данных.
- **Когда:** Вопросы с очевидным форматом (например, "Отфильтруй логи по уровню критичности").
- **Ограничение:** Работает плохо, если нужен специфический формат вывода или редкая предметная область.


### One-shot
- **Что это:** Даёшь один пример, чтобы задать формат или стиль.
- **Когда:** Нужно, чтобы модель выдавала ответ в строгом JSON/YAML или в определённой структуре.
- **Пример:** *"Вот как я хочу, чтобы ты описывал XSS-уязвимость. Теперь опиши эту SSRF по той же схеме".*


### Few-shot
- **Что это:** Даёшь 2–5 примеров, которые покрывают разные кейсы (нормальные, подозрительные, критические).
- **Когда:** Есть сложная классификация (например, аномалии в трафике или разграничение угроз по типам).
- **Правило:** Примеры должны быть разнообразными, покрывать граничные случаи и иметь одинаковую структуру (чтобы модель не путалась).


## 2. Chain-of-Thought (CoT) — Цепочка рассуждений

**Суть:** Модель не просто даёт ответ, а показывает, **как она к нему пришла**.

Вместо:
> *"Да, это подозрительно".*

Модель пишет:
> *"1. Файл имеет двойное расширение (.pdf.exe) — признак маскировки. 2. Пришёл из письма — вектор доставки малвари. 3. Легитимные PDF не имеют .exe. Вывод: это угроза высокого приоритета".*


### Zero-shot CoT
- Просто добавляешь в конец промпта: **`"Let's think step by step"`** (или "Давай подумаем пошагово").
- Работает даже без примеров, заставляя модель рассуждать вслух.

### CoT + Few-shot
- Добавляешь в примеры **не только ответ**, но и **рассуждение**.
- Модель копирует паттерн: видит, как ты размышляешь, и делает так же.

### Важное ограничение:
- CoT хорошо работает только на моделях **от 100B параметров**.
- Маленькие модели могут генерировать рассуждения, которые звучат убедительно, но ведут к неправильному ответу.


## 3. Prompt Templates (Шаблоны промптов)

**Суть:** Заготовленные структуры для повторяющихся задач.

**Пример шаблона для анализа кода:**
*"Проверь этот [LANGUAGE] код на [VULNERABILITY_TYPES]. Контекст: [PURPOSE]. Код: [CODE_BLOCK]. В выводе дай: 1) уязвимости с severity, 2) строки кода, 3) как исправить, 4) пример безопасного кода".*

**Почему это круто:**
- Обеспечивает единообразие в команде.
- Экономит время, когда задача повторяется (анализ логов, ревью кода, расследование инцидентов).
- Помогает не забывать важные пункты (например, всегда указывать строки кода и severity).


## 💡 Для безопасности (Security-специфичные применения)

- **Zero-shot:** «Классифицируй этот событийный лог».
- **One-shot:** «Вот как я хочу, чтобы ты описывал IDOR. Теперь опиши эту найденную XSS по той же схеме».
- **Few-shot:** «Вот 3 примера фишинговых писем и 3 легитимных. Теперь классифицируй это письмо».
- **CoT:** «Проанализируй цепочку атаки: как злоумышленник мог попасть из точки А в точку Б?»
- **Шаблон:** «Каждый раз, когда я прошу проанализировать логин-брутфорс, выдавай ответ по этой структуре: временная метка, источник, целевой юзер, результат».


## ⚠️ Главный вывод

Эти техники **не делают промпт "лучше" в общем смысле**. Они делают его **специализированным под конкретную задачу**.
