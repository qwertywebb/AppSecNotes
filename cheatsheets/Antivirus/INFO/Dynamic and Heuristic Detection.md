**Динамическое, эвристическое и поведенческое обнаружение**


### 1. Динамическое обнаружение

Анализирует **поведение файла во время выполнения**, а не статическую структуру.

**Методы:**
- **Мониторинг Windows API** — отслеживает подозрительные вызовы (например, `CreateRemoteThread`, `WriteProcessMemory`) через хуки.
- **Песочница (Sandbox)** — файл запускается в изолированной среде, где анализируются его действия: доступ к файлам, сетевые соединения, изменения в реестре.

**Как обойти:**
- Проверка на виртуальное окружение (песочницу).
- Отложенное выполнение вредоносной логики (таймеры).
- Запуск полезной нагрузки только при наличии реального пользовательского ввода (клик мыши, нажатие клавиши).


### 2. Эвристическое и поведенческое обнаружение

Ищет **паттерны**, характерные для вредоносного ПО, даже если точная сигнатура неизвестна.

**Статическая эвристика:**
- Декомпилирует код и сравнивает его с известными вредоносными фрагментами.
- Если совпадение превышает порог (например, 80%) — файл считается подозрительным.

**Динамическая эвристика:**
- Основывается на **правилах поведения**.
- Примеры правил:
  - Процесс пытается взаимодействовать с `lsass.exe` (кража учётных данных).
  - Процесс открывает сетевой порт и ждёт команды от C2-сервера.


### 3. Как работает современный антивирус (все вместе)

1. **Распаковка** — если файл упакован (UPX, шифрование), AV его распаковывает.
2. **Декомпиляция/парсинг** — извлекает структуру PE-файла, строки, импорты.
3. **Статический анализ** — сверяет с базой сигнатур и эвристическими правилами.
4. **Динамический анализ** — если нужно, запускает в песочнице.
5. **Пов Поведенческий анализ** — проверяет, есть ли подозрительные действия в реальном времени.

**Пример:**  
Файл `Foobar.zip` → распаковка → `Foobar.exe` → проверка упаковщика → анализ PE-заголовков → проверка по базам → результат: вредоносный/чистый.


### 4. Как обойти

| Метод | Пример |
|-------|--------|
| **Обход песочницы** | Проверка на наличие реального окружения (например, разрешение экрана, мышь, время работы системы). |
| **Отложенное выполнение** | Задержка перед запуском полезной нагрузки (`Sleep(60000)`). |
| **Шифрование полезной нагрузки** | Распаковка в памяти, а не на диске. |
| **Использование легитимных API** | Замена подозрительных вызовов на легитимные (например, `VirtualAlloc` → `HeapAlloc`). |
| **Разрыв цепочки вызовов** | Внедрение в легитимный процесс через `SetWindowsHookEx`, а не `CreateRemoteThread`. |


### 5. Итог

- **Статика** — быстрая, но слабая против изменённых файлов.
- **Динамика** — мощная, но ресурсозатратная (песочница, хуки).
- **Эвристика** — ищет поведение, а не конкретный код.
- **Современный AV** — комбинирует все три метода.

**Для RedTeam:**  
Самый простой путь обхода — **шифрование + отложенное выполнение + проверка на песочницу**. Это заставит AV потратить ресурсы на анализ, а при реальном запуске полезная нагрузка выполнится.
