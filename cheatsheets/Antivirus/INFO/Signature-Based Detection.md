**Конспект: Статическое обнаружение (Signature-Based Detection)**


### 1. Суть метода
Антивирус **сравнивает файлы с базой сигнатур** (уникальных "отпечатков" вредоносного кода).  
Если находит совпадение — файл **помечается как вредоносный**.

**Что ищет:**
- Уникальные строки (например, `C:\Users\...\AV-Check.pdb`).
- Хеши (MD5, SHA1).
- Определённые байтовые последовательности (например, начало `MZ` у `.exe`).
- CRC-суммы.

**Главный минус:**  
Сигнатура файла меняется при любом изменении (перекомпиляция, упаковка, шифрование). Как только злоумышленник меняет пару байтов, старая сигнатура перестаёт работать.


### 2. Как это выглядит на практике (ClamAV)

- **ClamAV** — пример антивируса с открытым кодом.
- Сканирует файлы по базе сигнатур.
- Если сигнатура известна → `FOUND`.
- Если нет → `OK` (ложноположительный или пропуск).

**Пример:**
- `backdoor1.exe` — найден, т.к. его байты уже есть в базе ClamAV.
- `backdoor2.exe` — пропущен, т.к. злоумышленник **зашифровал** шелл-код, и байты изменились.


### 3. Создание своей сигнатуры (для обучения)

Можно создать **свою базу сигнатур** (`.hdb`) через `sigtool`:

```cmd
sigtool --md5 backdoor2.exe > thm.hdb
```

Теперь ClamAV может искать по этому хешу:

```cmd
clamscan -d thm.hdb backdoor2.exe
```

**Вывод:** `backdoor2.exe: backdoor2.exe.UNOFFICIAL FOUND`


### 4. YARA — гибкое правило для статического анализа

**YARA** — язык для создания правил обнаружения. Вместо фиксированного хеша мы пишем **условия**.

**Пример правила:**
```yara
rule thm_demo_rule {
    strings:
        $a = "C:\\Users\\thm\\...\\AV-Check.pdb"
        $b = "MZ"
    condition:
        $b at 0 and $a
}
```

- `$b at 0` — файл начинается с `MZ` (исполняемый).
- `$a` — внутри есть путь отладки.
- `and` — оба условия должны совпасть.

**Важно:**
- Без проверки на `MZ` правило ловит **любой текстовый файл**, содержащий эту строку (ложные срабатывания).
- Добавление условия `$b at 0` делает правило точным.


### 5. Как статику обходят
| Метод обхода | Пример |
|--------------|--------|
| **Шифрование** | Закодировать шелл-код XOR/Base64 |
| **Упаковка** | Использовать UPX, Enigma |
| **Изменение строк** | Заменить `C:\Users\...` на что-то другое |
| **Обфускация** | Переименовать функции, добавить мусорный код |
| **Перекомпиляция** | Собрать бинарник заново — новый хеш |


### 6. Вывод

- Статика — **самый быстрый и простой** метод.
- Но она **бесполезна** против модифицированных/зашифрованных файлов.
- Антивирусные базы нужно постоянно обновлять.
- Обход статики — это **изменение сигнатуры**: шифрование, упаковка, обфускация.

**Правило для RedTeam:**  
Если хочешь обойти статический антивирус — **зашифруй шелл-код** и **упакуй** бинарник. Сигнатура изменится, и старый антивирус тебя не увидит.
