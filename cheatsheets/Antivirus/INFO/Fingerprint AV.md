**AV-среды, Fingerprinting и Обход**


### 1. Где тестировать payloads

**VirusTotal** — 70+ антивирусов, но **все файлы делятся с вендорами**. Сжигает рабочие инструменты.  
**Альтернативы (без шэринга):**
- AntiScanMe (6 сканов/день)
- Jotti (ограничения по размеру)


### 2. Как узнать, какой AV стоит на машине

**Методы:**
- **Имена процессов** — самый быстрый способ. Проверяем список запущенных процессов через `tasklist` или WMI.
- **Имена служб** (например, `WinDefend` — Defender).
- **Реестр, папки, файлы** (например, `C:\Program Files\Windows Defender`).

**Инструменты:**
- **SharpEDRChecker** — C#-утилита, которая проверяет всё вышеперечисленное.
- **Самописный скрипт** через WMI-запрос:  
  `select * from win32_process` → сверяем с массивом известных AV-процессов.


### 3. Основные процессы, которые появляются при наличии AV

| **Антивирус** | **Имя процесса(ов)** |
| :--- | :--- |
| **Microsoft Defender** | `MsMpEng.exe`, `NisSrv.exe` (защита в реальном времени) |
| **Kaspersky** | `avp.exe`, `ksde.exe` |
| **Bitdefender** | `bdagent.exe`, `vsserv.exe` |
| **Avast** | `afwServ.exe`, `AvastSvc.exe` |
| **AVG** | `AVGSvc.exe` |
| **Norton** | `NortonSecurity.exe` |
| **McAfee** | `MCAPExe.exe`, `mfemms.exe` |
| **Trend Micro** | `TMBMSRV.exe` |
| **Avira** | `avguard.exe`, `Avira.ServiceHost.exe` |
| **Panda** | `PavPrSvr.exe` |

**Для проверки вручную (cmd):**
```cmd
tasklist | findstr /i "MsMpEng.exe avp.exe bdagent.exe AvastSvc.exe"
```


### 4. Почему простые C#-скрипты детектятся

Код, который делает WMI-запросы, может:
- Попасть под **сигнатуры** (внезапно).
- Вызвать срабатывание **поведенческих правил** (Process Ghosting, Suspicious WMI).
- Даже легитимный `AV-Check.exe` детектится несколькими AV как false-positive.

**Вывод:** Исполняемые файлы, даже безопасные, могут детектиться из-за «подозрительного» поведения.


### 5. Практический вывод

- **Не грузи полезные пейлоады в VirusTotal**, если не хочешь их сжечь.
- На этапе разведки используй **SharpEDRChecker** или скрипты на PowerShell/C# для идентификации AV.
- Если код детектится, попробуй:
  - Сменить способ перебора (WMI → Win32 API).
  - Обфусцировать код.
  - Скомпилировать под другую архитектуру (x86 vs x64).

**Итог:** Fingerprinting AV — обязательный этап перед деплоем полезной нагрузки. Самый быстрый способ — проверить список процессов на наличие процессов из таблицы выше. Если процесс найден — знаешь, с чем бороться.
