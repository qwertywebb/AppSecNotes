# ICMP-скан

## 1. Что такое ICMP-скан

**ICMP (Internet Control Message Protocol)** — используется для диагностики сети.  
В контексте Nmap — для проверки, жив ли хост.

**Идея:**  
Отправляем специальный ICMP-пакет → если хост отвечает → он жив.


## 2. Проблема с ICMP

- **Фаерволы часто блокируют ICMP.**
- Например, Windows по умолчанию блокирует ICMP Echo (пинг) через встроенный брандмауэр.

**Вывод:**  
Нельзя полагаться только на один тип ICMP-запросов. Нужно пробовать разные.


## 3. Типы ICMP-сканов в Nmap

| Тип скана | ICMP Тип | Опция Nmap | Что делает |
| :--- | :--- | :--- | :--- |
| **Echo (пинг)** | Type 8 (запрос) → Type 0 (ответ) | `-PE` | Классический пинг |
| **Timestamp** | Type 13 (запрос) → Type 14 (ответ) | `-PP` | Запрос времени |
| **Address Mask** | Type 17 (запрос) → Type 18 (ответ) | `-PM` | Запрос маски подсети |


## 4. ICMP Echo (`-PE`)

**Самый известный способ.**  
Отправляет ICMP Echo Request и ждёт Echo Reply.

**Команда:**
```bash
nmap -PE -sn TARGETS
```

**Пример:**
```bash
nmap -PE -sn 10.200.6.0/24
```

**Результат:**
```
Host is up (0.069s latency).
```

**Как выглядит в Wireshark:**  
Один источник отправляет ICMP-запросы на все IP в подсети.


## 5. ICMP Timestamp (`-PP`)

**Используется, когда Echo заблокирован.**  
Отправляет ICMP Timestamp Request (Type 13) и ждёт Timestamp Reply (Type 14).

**Команда:**
```bash
nmap -PP -sn TARGETS
```

**Пример:**
```bash
nmap -PP -sn 10.200.6.0/24
```

**Результат:**
```
Host is up.
```

**Особенность:**  
Иногда Timestamp проходит там, где Echo заблокирован.


## 6. ICMP Address Mask (`-PM`)

**Самый редко используемый.**  
Отправляет Address Mask Request (Type 17) и ждёт Address Mask Reply (Type 18).

**Пример:**
```bash
nmap -PM -sn 10.200.6.0/24
```

**Результат:**  
Часто блокируется фаерволом → 0 хостов найдено.

**Особенность:**  
Этот метод часто не работает, потому что многие системы не отвечают на Address Mask запросы.


## 7. Почему нужно пробовать разные методы

| Сценарий | Что делать |
| :--- | :--- |
| **Echo заблокирован** | Попробовать Timestamp (`-PP`) |
| **Timestamp заблокирован** | Попробовать Echo (`-PE`) |
| **Всё заблокировано** | Использовать TCP SYN (порт 80/443) или ARP (в локальной сети) |


## 8. Важно: ARP всегда в приоритете

Если цель **в одной подсети с тобой**, Nmap **всегда сначала делает ARP-запрос**, а только потом ICMP.  
Это происходит автоматически, даже если ты указал `-PE`.


## 📌 Итог

| Метод | Опция | Надёжность |
| :--- | :--- | :--- |
| **Echo** | `-PE` | Часто блокируется |
| **Timestamp** | `-PP` | Может работать, когда Echo заблокирован |
| **Address Mask** | `-PM` | Почти всегда блокируется |

> **Вывод:**  
> Не полагайся на один тип ICMP. Используй комбинацию методов:  
> **ARP** (локальная сеть), **ICMP Echo**, **ICMP Timestamp**, **TCP SYN** (порты 80/443).
