# Конспект: обход файрволов через поля IP-заголовка (Nmap)

## Введение

Файрволы и IDS/IPS анализируют пакеты. Если изменить поля IP-заголовка (TTL, IP Options, checksum), можно обмануть фильтр: он не распознает пакет как подозрительный или пропустит его. Nmap даёт три инструмента для этого.


## 1. `--ttl VALUE` — управление Time-to-Live

TTL — поле в IP-заголовке. Уменьшается на 1 на каждом маршрутизаторе. Когда TTL = 0, пакет отбрасывается (и отправителю приходит ICMP Time Exceeded).

Зачем менять: если поставить маленький TTL (1, 2), пакет не дойдёт до цели — он «умрёт» на первом-втором маршрутизаторе. Это можно использовать, чтобы проверить топологию или обойти фильтр, который смотрит на TTL.

Синтаксис:

```bash
nmap -sS -Pn --ttl 81 -F <target>
```

Пример из задания:

```bash
nmap -sS -Pn --ttl 1 -F 10.130.161.127
```

Что происходит: TTL = 1 → пакет умирает на первом маршрутизаторе → до цели не доходит → все порты filtered.

```bash
nmap -sS -Pn --ttl 2 -F 10.130.161.127
```

TTL = 2 → пакет умирает на втором маршрутизаторе → тоже не доходит.

Вывод: при маленьком TTL пакеты не доходят до цели, и Nmap показывает все порты filtered (или 0 открытых).

---

## 2. `--ip-options` — управление полем IP Options

IP Options — необязательное поле в IP-заголовке. Используется для record-route, timestamp, source routing.

Синтаксис:

```bash
nmap --ip-options HEX_STRING <target>
```

Или буквенные сокращения:

| Буква | Что делает |
|---|---|
| R | record-route |
| T | record-timestamp |
| U | record-route и record-timestamp |
| L | loose source routing (список IP через пробел) |
| S | strict source routing (список IP через пробел) |

Пример:

```bash
nmap -sS -Pn --ip-options "R" -F <target>
```

Loose/strict source routing — можно заставить пакет идти по определённому маршруту, чтобы обойти фильтр.


## 3. `--badsum` — неправильная контрольная сумма

Checksum — поле в TCP/UDP-заголовке. Проверяет целостность пакета.

`--badsum` — отправляет пакеты с намеренно неправильной checksum.

Зачем: некоторые системы отбрасывают пакеты с плохой checksum, другие — нет. Это позволяет определить, какая ОС или фильтр стоит на пути.

Синтаксис:

```bash
nmap -sS -Pn --badsum -F <target>
```

Пример из задания:

```bash
nmap -sS -Pn --badsum -F 10.130.161.127
```

Результат:

```
All 100 scanned ports on 10.130.161.127 are filtered
```

Вывод: цель отбросила все пакеты с плохой checksum → все порты filtered. Если бы цель принимала пакеты с плохой checksum — Nmap показал бы открытые порты.


## 4. Сводная таблица

| Приём | Опция Nmap | Что делает |
|---|---|---|
| TTL | `--ttl VALUE` | Устанавливает Time-to-Live |
| IP Options | `--ip-options OPTIONS` | Задаёт поле IP Options (R/T/U/L/S) |
| Bad checksum | `--badsum` | Отправляет пакеты с неправильной checksum |


## 5. Практический смысл

`--ttl` — проверка топологии (сколько хопов до цели) и обход фильтров, которые смотрят на TTL.

`--ip-options` — source routing (обход фильтров по маршруту), record-route (разведка).

`--badsum` — определение ОС/фильтра (кто отбрасывает плохие checksum).

Все три приёма — часть арсенала evasion в Nmap.

## 6. Быстрая шпаргалка

```bash
# TTL
nmap -sS -Pn --ttl 1 -F <target>
nmap -sS -Pn --ttl 81 -F <target>

# IP Options
nmap -sS -Pn --ip-options "R" -F <target>
nmap -sS -Pn --ip-options "L 10.0.0.1 10.0.0.2" -F <target>

# Bad checksum
nmap -sS -Pn --badsum -F <target>
```
