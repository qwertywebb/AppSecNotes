# Как программы вызывают Win32 API (обход проблемы ASLR)

## 1. Проблема: ASLR (Address Space Layout Randomization)

**ASLR** — механизм защиты Windows, который при каждом запуске программы случайным образом меняет адреса DLL и функций в памяти.

**Зачем это нужно:**
Чтобы нельзя было заранее знать, по какому адресу находится нужная функция (например, `CreateProcess` или `VirtualAlloc`).

**Что это означает для разработчика:**
Адрес функции постоянно меняется, поэтому нельзя просто взять и вызвать её по фиксированному адресу. Сначала нужно узнать, где она находится в памяти.


## 2. Решение: получить адрес функции

Все функции Win32 API находятся внутри DLL (например, `kernel32.dll`, `user32.dll`, `advapi32.dll`).

Чтобы вызвать функцию, программе сначала нужно получить её текущий адрес в памяти.

В зависимости от языка программирования это делается по-разному.

| Способ                  | Для чего              | Языки      |
| :---------------------- | :-------------------- | :--------- |
| **Windows Header File** | Для нативных программ | C, C++     |
| **P/Invoke**            | Для программ на .NET  | C#, VB.NET |


## 3. Windows Header File (для C/C++)

### Как работает

1. Подключаем заголовочный файл:

```c
#include <windows.h>
```

2. После этого можно вызывать функции Win32 API как обычные функции.

3. При запуске программы Windows сама:

   * загружает нужные DLL;
   * находит адреса всех используемых функций;
   * подставляет эти адреса автоматически.

Поэтому программисту не нужно вручную искать адрес функции.

### Пример

```c
#include <windows.h>

int main()
{
    MessageBox(NULL, "Hello", "Title", MB_OK);
    return 0;
}
```

### Что происходит внутри

Когда компилятор видит вызов

```c
MessageBox(...)
```

он понимает, что эта функция находится в `user32.dll`.

Во время запуска программы Windows загружает `user32.dll`, находит настоящий адрес `MessageBox` и делает так, чтобы программа вызывала именно этот адрес.


## 4. P/Invoke (для C# / .NET)

### Что это

C# работает внутри платформы .NET.

Поэтому он не умеет напрямую вызывать функции Windows.

Для этого существует механизм **P/Invoke (Platform Invoke)**.

Он позволяет вызвать функцию из обычной DLL Windows прямо из кода C#.

### Как работает

1. Указываем, из какой DLL нужно взять функцию.

2. Говорим, что сама функция находится вне нашего кода (`extern`).

3. После этого вызываем её как обычный метод C#.

### Пример

```csharp
using System;
using System.Runtime.InteropServices;

public class Program
{
    [DllImport("user32.dll", CharSet = CharSet.Unicode)]
    private static extern int MessageBox(
        IntPtr hWnd,
        string lpText,
        string lpCaption,
        uint uType);

    public static void Main()
    {
        MessageBox(IntPtr.Zero, "Hello from C#!", "Title", 0);
    }
}
```

### Что происходит внутри

Когда программа запускается:

* .NET загружает `user32.dll`;
* находит функцию `MessageBox`;
* получает её адрес;
* вызывает её так, как будто это обычный метод C#.


## 5. Сравнение двух подходов

| Характеристика               | Windows Header File (C/C++) | P/Invoke (C#)                                          |
| :--------------------------- | :-------------------------- | :----------------------------------------------------- |
| **Язык**                     | C, C++                      | C#, VB.NET                                             |
| **Тип программы**            | Нативная                    | .NET                                                   |
| **Как вызывается Win32 API** | Через `windows.h`           | Через `[DllImport]`                                    |
| **Кто ищет адрес функции**   | Windows                     | .NET                                                   |
| **Что пишет разработчик**    | Просто вызывает функцию     | Описывает функцию через `DllImport`, затем вызывает её |


## 6. Почему это важно для Red Team

Практически все техники работы с памятью используют Win32 API.

Например:

* выделение памяти (`VirtualAlloc`);
* создание процессов (`CreateProcess`);
* создание потоков (`CreateThread`);
* работа с памятью другого процесса (`WriteProcessMemory`);
* запуск удалённого потока (`CreateRemoteThread`).

Поэтому важно понимать, как программа вообще получает доступ к этим функциям.

В дальнейшем ты встретишь код, который вообще не использует `windows.h` или `DllImport`, а получает адреса функций вручную через `LoadLibrary`, `GetModuleHandle` и `GetProcAddress`. Это уже следующий уровень работы с Win32 API.


# 📌 Итог

* **Win32 API** — это набор функций Windows, которые находятся внутри DLL.
* Из-за **ASLR** адреса этих функций постоянно меняются.
* Поэтому перед вызовом функции программа должна узнать её текущий адрес.
* В **C/C++** это автоматически делает Windows после подключения `windows.h`.
* В **C#** для этого используется механизм **P/Invoke** (`DllImport`).
* В обоих случаях разработчик может вызывать функции Windows почти так же просто, как обычные функции своего языка.

> **`windows.h` лишь позволяет удобно использовать Win32 API, а реальные адреса функций во время запуска находит загрузчик Windows (Windows Loader).**
