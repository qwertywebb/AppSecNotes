## Альтернативные методы выполнения шелл-кода

### Введение

Когда стандартные методы выполнения (CreateThread / CreateRemoteThread) не работают из-за EDR, хуков или мониторинга, нужно использовать альтернативные техники. Каждая из них имеет свои особенности и подходит для разных сценариев.


### 1. Invoking Function Pointers (Вызов через указатель на функцию)

**Что это:** Метод, при котором мы приводим указатель на наш шелл-код к указателю на функцию и вызываем её. Это работает только с памятью в локальном процессе (не для удалённого инжекта).

**Как выглядит:**
```c
((void(*)())addressPointer)();
```

**Разбор:**
- `void(*)()` — объявление указателя на функцию, которая ничего не принимает и ничего не возвращает.
- `(void(*)())addressPointer` — приводим наш адрес к нужному типу.
- `()` — вызываем функцию.

**Преимущества:** Не использует API-вызовы для выполнения (только само приведение типов). Сложнее детектится EDR.

**Недостатки:** Работает только с локальной памятью (в своём процессе). Невозможно использовать для внедрения в чужой процесс.

**Когда использовать:** Для выполнения кода в своём процессе, если CreateThread заблокирован.


### 2. Asynchronous Procedure Calls (APC)

**Что это:** APC — это функция, которая выполняется асинхронно в контексте конкретного потока. Мы ставим её в очередь через `QueueUserAPC`, и она выполняется, когда поток переходит в "alertable state" (ожидание завершения операции).

**Как работает в инжекте:**

1. Выделяем память и пишем шелл-код (как в классическом инжекте).
2. Используем `QueueUserAPC`, чтобы поставить наш шелл-код в очередь к целевому потоку.
3. Вызываем `ResumeThread` (если поток приостановлен) или `WaitForSingleObject`, чтобы поток перешёл в alertable состояние.
4. Когда поток становится alertable, APC-функция выполняется.

**Код:**
```c
QueueUserAPC(
    (PAPCFUNC)addressPointer,  // Наш шелл-код как APC-функция
    pinfo.hThread,             // Поток-жертва
    (ULONG_PTR)NULL
);
ResumeThread(pinfo.hThread);
WaitForSingleObject(pinfo.hThread, INFINITE);
```

**Преимущества:** Не создаётся новый поток (CreateRemoteThread не используется), что обходит многие детекты.

**Недостатки:** Требует, чтобы поток был в alertable состоянии. EDR уже научились детектировать APC-атаки (например, через отслеживание `QueueUserAPC` в сочетании с `VirtualAllocEx`).

**Когда использовать:** Когда CreateRemoteThread заблокирован, а целевой процесс имеет потоки, которые можно перевести в alertable состояние.


### 3. Section Manipulation (Манипуляция секциями PE-файла)

**Что это:** Техника, при которой мы модифицируем PE-файл (переносим или изменяем секции, таблицы релокаций) для выполнения кода. Мы не просто пишем шелл-код, а работаем на уровне структуры исполняемого файла.

**Как работает:**

1. Получаем PE-дамп (например, через `xxd` из DLL или EXE-файла).
2. Парсим заголовки PE-файла: DOS-заголовок (`e_lfanew`), NT-заголовки, таблицы секций.
3. Используем математические вычисления для перемещения по данным и изменения секций (например, `.text` или `.data`).
4. Обновляем указатели в таблицах релокаций, чтобы код выполнялся корректно.

**Основные техники внутри:**
- **RVA Entry Point Parsing** — парсинг точки входа (RVA) для перенаправления выполнения.
- **Section Mapping** — отображение секций в памяти с последующим изменением.
- **Relocation Table Parsing** — работа с таблицами релокаций для поддержки разных базовых адресов.

**Преимущества:** Очень сложно детектится, так как мы работаем с легитимными структурами PE-файлов.

**Недостатки:** Сложность реализации. Требует глубокого понимания формата PE.

**Когда использовать:** В продвинутых атаках, где стандартные инжекты детектятся EDR. Часто используется в сочетании с другими техниками (например, Process Hollowing).


### Сравнение методов

| Метод | Где выполняется | API-вызовы | Сложность детекта | Сложность реализации |
|-------|----------------|-----------|-------------------|---------------------|
| **Invoking Function Pointers** | В своём процессе | Нет (только каст) | Низкая | Очень низкая |
| **APC** | В чужом процессе | QueueUserAPC | Средняя (уже детектятся) | Средняя |
| **Section Manipulation** | В чужом процессе | Минимум | Высокая | Очень высокая |


### Практические выводы

1. **Если нужно быстро выполнить код в своём процессе** — используй Invoking Function Pointers.
2. **Если CreateRemoteThread не работает** — попробуй APC (но учти, что EDR уже следят за этим).
3. **Если нужна максимальная скрытность** — Section Manipulation, но будь готов к сложной реализации.
4. **Можно комбинировать**: например, выделить память через `VirtualAllocEx`, записать шелл-код, а выполнить через APC или Section Manipulation.


### Простыми словами

- **Invoking Function Pointers** — ты говоришь компьютеру: "Вот адрес с кодом, выполни его". И он выполняет. Просто и без лишних вызовов.
- **APC** — ты просишь систему: "Добавь мой код в очередь к такому-то потоку". Когда поток будет свободен, он выполнит его.
- **Section Manipulation** — ты редактируешь сам исполняемый файл (как книгу), меняешь содержимое страниц и указатели, чтобы при запуске выполнялся твой код вместо оригинального.


### На интервью спросят

- Чем APC отличается от CreateRemoteThread? (Не создаёт новый поток, использует существующий)
- Почему Invoking Function Pointers сложнее детектится? (Нет API-вызовов, только каст указателей)
- Что такое alertable состояние потока? (Поток ожидает завершения операции и готов принять APC)
- Почему Section Manipulation сложно реализовать? (Требует глубокого понимания PE-формата и релокаций)
