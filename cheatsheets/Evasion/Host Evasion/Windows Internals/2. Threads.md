# 🧵 Конспект: Потоки (Threads)


## 1. Что такое поток (Thread)

**Поток — это "исполнитель" внутри процесса.**  
Процесс — это программа (например, `notepad.exe`), а поток — это то, что **реально выполняет код**.

**Простыми словами:**  
Процесс — это дом, а поток — это рабочий, который внутри него выполняет задачи.


## 2. Зачем нужны потоки

- Позволяют процессу **делать несколько дел одновременно** (например, печатать и сохранять файл).
- Дают возможность **выполнять код параллельно**, если несколько ядер процессора.


## 3. Чем поток отличается от процесса

| Процесс | Поток |
| :--- | :--- |
| Содержит память, код, ресурсы | Работает внутри процесса, использует его ресурсы |
| Тяжелее (создаётся дольше) | Легче (создаётся быстрее) |
| Имеет своё адресное пространство | Разделяет память с другими потоками процесса |


## 4. Что есть у каждого потока (индивидуально)

| Компонент | Что это |
| :--- | :--- |
| **Stack** | Стек — данные, связанные с этим потоком (вызовы функций, локальные переменные) |
| **Thread Local Storage** | Хранилище для уникальных данных потока |
| **Stack Argument** | Уникальный идентификатор, присвоенный потоку |
| **Context Structure** | Регистры процессора, сохранённые для этого потока |


## 5. Почему потоки важны для безопасности

- Злоумышленники могут **внедрять код в потоки** (например, инъекция в чужой процесс).
- **Атаки на потоки** позволяют выполнять код с правами другого процесса.
- Часто используются в **цепочках атак** вместе с другими техниками.


## 6. Как это связано с реальными атаками

- Вредоносное ПО может создавать **новые потоки** в легитимных процессах.
- Использует **перехват потоков** для выполнения команд от имени жертвы.
- Может **приостанавливать или изменять контекст** потока для обхода защиты.


## 📌 Итог

> **Процесс — это контейнер. Поток — это тот, кто внутри него работает.**  
> Потоки делят ресурсы процесса, но имеют свои стеки и контекст.  
> Они критичны для выполнения кода и часто используются в атаках.
