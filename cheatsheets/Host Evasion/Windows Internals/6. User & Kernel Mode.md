# 🧠 Windows Internals: Режимы процессора, системные вызовы и внедрение кода 

## 1. Что такое User Mode и Kernel Mode (режимы процессора)

Представь, что Windows — это **банк**.

| Режим | Что это | Кто там работает |
| :--- | :--- | :--- |
| **User Mode** (Пользовательский режим) | Обычный зал банка. Ты видишь только свою ячейку. | Твои программы (браузер, игры, Notepad) |
| **Kernel Mode** (Режим ядра) | Хранилище банка (сейфы, серверы, всё самое важное). | Ядро Windows (драйверы, память, оборудование) |

**Почему так сделано:**  
Чтобы обычная программа не могла случайно (или специально) сломать систему или украсть чужие данные.


## 2. Как программа попадает в Kernel Mode

Программа в User Mode **не может** сама трогать память, оборудование или другие процессы.  
Для этого она делает **системный вызов (System Call)**.

**Аналогия:**  
Ты (программа) просишь сотрудника банка (ядро) сделать что-то за тебя — например, открыть чужую ячейку (память другого процесса). Сотрудник проверяет твои права и, если можно, выполняет действие.


## 3. Что такое API (Win32 API)

Это **набор готовых функций**, которые Windows предоставляет программам.

**Примеры:**  
- `OpenProcess` — открыть процесс  
- `VirtualAllocEx` — выделить память в другом процессе  
- `WriteProcessMemory` — записать данные в память другого процесса  
- `CreateRemoteThread` — создать поток в другом процессе

Эти функции — **мост** между User Mode и Kernel Mode.

## 4. Как выглядит внедрение кода (Process Injection) — по шагам

Допустим, ты хочешь запустить свой код внутри `notepad.exe` (чтобы он выполнился от имени Notepad'а).

### Шаг 1: Открыть процесс
```cpp
HANDLE hProcess = OpenProcess(PROCESS_ALL_ACCESS, FALSE, PID);
```
Ты говоришь Windows: «Дай мне доступ к процессу с ID = PID».

### Шаг 2: Выделить память в этом процессе
```cpp
remoteBuffer = VirtualAllocEx(hProcess, NULL, sizeof(payload), MEM_RESERVE | MEM_COMMIT, PAGE_EXECUTE_READWRITE);
```
Ты говоришь: «Выдели мне кусочек памяти в чужом процессе».

### Шаг 3: Записать туда свой код
```cpp
WriteProcessMemory(hProcess, remoteBuffer, payload, sizeof(payload), NULL);
```
Ты копируешь свой код (payload) в выделенную память.

### Шаг 4: Запустить этот код как поток
```cpp
CreateRemoteThread(hProcess, NULL, 0, (LPTHREAD_START_ROUTINE)remoteBuffer, NULL, 0, NULL);
```
Ты создаёшь новый поток в чужом процессе, который начинает выполнять твой код.

## 5. Зачем это нужно злоумышленникам

| Техника | Что делает |
| :--- | :--- |
| **Process Injection** | Внедряет код в чужой процесс, чтобы выполнить его с правами того процесса |
| **DLL Injection** | Загружает DLL в чужой процесс |
| **Thread Injection** | Создаёт поток в чужом процессе |
| **APC Injection** | Внедряет код через асинхронный вызов процедуры |

**Цель:**  
Скрыть свои действия (вредоносный код работает внутри легитимного процесса, его сложнее обнаружить).

---

## 6. Что происходит в коде (кратко)

```cpp
OpenProcess()          → Получить доступ к процессу
VirtualAllocEx()       → Выделить память в чужом процессе
WriteProcessMemory()   → Записать туда свой код
CreateRemoteThread()   → Запустить этот код
```


## 📌 Итог

| Вопрос | Ответ |
| :--- | :--- |
| **Что такое User Mode?** | Режим, где работают обычные программы. Нет доступа к оборудованию и чужой памяти. |
| **Что такое Kernel Mode?** | Режим ядра. Полный доступ ко всему. |
| **Как программа попадает в Kernel Mode?** | Через системные вызовы (System Calls) и Win32 API. |
| **Что такое Process Injection?** | Внедрение кода в чужой процесс через OpenProcess → VirtualAllocEx → WriteProcessMemory → CreateRemoteThread. |
| **Зачем это делают?** | Чтобы выполнить код с правами другого процесса и скрыть свои действия. |

> **Процессор переключается между режимами при каждом системном вызове.**  
> Программа не имеет доступа к ядру напрямую — она просит ядро выполнить действие через API.
