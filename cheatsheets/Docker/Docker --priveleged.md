Побег из привилегированного контейнера — это одна из самых опасных уязвимостей в Docker, потому что флаг `--privileged` фактически снимает все ограничения изоляции и даёт процессу внутри контейнера почти те же права, что и на хосте .

## Почему `--privileged` так опасен?

`--privileged` дает контейнеру все возможные Linux-капы (capabilities), доступ ко всем устройствам хоста и убирает ограничения cgroup . Это означает, что изоляция, которую Docker должен обеспечивать, просто перестаёт существовать .

## Основные векторы для побега

### 1. Монтирование диска хоста (Самый простой способ)

Это самый прямолинейный метод. Внутри привилегированного контейнера вы можете:

1.  Посмотреть, какие диски есть на хосте: `fdisk -l` 
2.  Создать папку и примонтировать корневой раздел хоста: `mkdir /h && mount /dev/sda1 /h` 
3.  Теперь вы имеете полный доступ к файловой системе хоста через папку `/h`. Вы можете читать `/h/etc/shadow`, добавлять SSH-ключи или даже использовать `chroot /h bash`, чтобы получить полноценный shell на хосте .

### 2. Использование Docker-сокета (`/var/run/docker.sock`)

Если этот сокет смонтирован в контейнер (что часто бывает в CI/CD или инструментах мониторинга), это фактически дает вам полный контроль над Docker-демоном хоста .

1.  Установите Docker CLI внутри контейнера: `apt-get install docker.io` 
2.  Создайте новый контейнер, который будет иметь доступ к хосту:

    ```bash
    docker run -it --rm \
      --privileged \  # Снова создаем привилегированный контейнер
      --volume /:/host \  # Монтируем корень хоста
      ubuntu:22.04 \
      chroot /host bash  # Получаем доступ к хосту 
    ```

### 3. Атака через `release_agent` (Cgroups v1)
cgroups (Control Groups) — это механизм ядра Linux, который позволяет ограничивать, учитывать и изолировать использование ресурсов (CPU, память, дисковый ввод-вывод, сеть) для группы процессов.

Эта атака сложнее, но `--privileged` дает для неё все необходимое. Она использует механизм `cgroups` v1, который позволяет выполнить произвольную команду на хосте при завершении процесса в cgroup .

1.  Найти или смонтировать cgroup v1: `mkdir /tmp/cgrp && mount -t cgroup -o rdma cgroup /tmp/cgrp` 
2.  Создать дочернюю cgroup: `mkdir /tmp/cgrp/x` 
3.  Включить уведомления: `echo 1 > /tmp/cgrp/x/notify_on_release` 
4.  Указать `release_agent` на ваш скрипт (используя путь, доступный на хосте) .
5.  Запустить процесс в этой cgroup и завершить его, что вызовет выполнение вашего скрипта на хосте с правами root .

### 4. Использование `nsenter`

Если контейнер запущен с флагом `--pid=host` (что часто бывает в связке с `--privileged`), он может видеть все процессы хоста. Тогда можно использовать утилиту `nsenter` для "входа" в пространство имен инициализационного процесса (PID 1) на хосте :

```bash
nsenter --target 1 --mount --uts --ipc --net --pid -- bash
```

Эта команда дает вам shell, который работает уже в контексте хоста .

## 💎 Краткий итог

Для быстрого и наглядного ответа используйте этот план:

*   **Главная причина:** `--privileged` снимает изоляцию, давая доступ ко всему, что делает хост .
*   **Самый простой путь:** Монтируете диск хоста (`mount /dev/sda1 /mnt`) и получаете доступ к его файловой системе .
*   **Самый "чистый" способ для следов:** Эксплуатация `cgroups release_agent`, которая выполняется на хосте без создания нового контейнера .
*   **Критическая ошибка:** Монтирование `docker.sock` внутрь контейнера дает атакующему полный контроль над Docker-демоном и позволяет запускать любые контейнеры на хосте .
