### 🧭 Какой компилятор выбрать?

В Linux вы чаще всего встретите два основных варианта: **GCC** и **Clang**.

| Компилятор | Команда | Когда использовать | Ключевые особенности |
| :--- | :--- | :--- | :--- |
| **GCC** | `gcc` (для C), `g++` (для C++) | По умолчанию в большинстве дистрибутивов Linux, при работе с ядром Linux или старыми проектами. | Стандарт де-факто, очень зрелый, поддерживает максимум платформ и расширений . |
| **Clang** | `clang` (для C), `clang++` (для C++) | Когда нужны более быстрая компиляция, более понятные сообщения об ошибках или современные инструменты анализа кода. | Основан на LLVM, часто даёт более читаемые ошибки, хорошая совместимость с GCC-опциями . |
| **cc** | `cc` | Это обычно просто **алиас (символическая ссылка)** на системный компилятор по умолчанию (чаще всего на `gcc` или `clang`). Используйте в скриптах для переносимости . | Не является отдельным компилятором, а указывает на тот, что выбран в системе. |

### 🛠️ Основные опции (актуальны и для GCC, и для Clang)

Большинство опций совпадает, так как Clang стремится быть совместимым с GCC.

**1. Управление этапами компиляции**
По умолчанию компилятор проходит 4 стадии: препроцессинг -> компиляция -> ассемблирование -> линковка. Эти флаги позволяют остановиться на нужной .

*   `-E`: Только препроцессинг (раскрыть макросы и `#include`).
*   `-S`: Остановиться после генерации ассемблерного кода (`.s`).
*   `-c`: Скомпилировать в объектный файл (`.o`), **но не линковать**. Это ключевой флаг для сборки проекта по частям.

**2. Управление выводом**
*   `-o <файл>`: Задать имя выходного файла. Без этого флага `gcc` создаст `a.out` .

**3. Линковка (Static vs Dynamic)**
*   **(по умолчанию)**: Динамическая линковка. Программа зависит от системных `.so` библиотек (например, `libc.so`). Компактнее, но требует наличия библиотек на целевой машине .
*   `-static`: **Статическая линковка**. Включает код библиотек прямо в исполняемый файл. Файл больше, но работает везде, где есть ядро (не зависит от версии `glibc` на целевой системе). Это то, что вам нужно было для `ofs` .
*   `-l<имя>`: Подключить библиотеку (например, `-lm` для математической библиотеки `libm`).
*   `-L<путь>`: Указать дополнительный путь для поиска библиотек.

**4. Предупреждения и отладка (очень важно для качества кода)**
*   `-Wall`: Включить **основные** предупреждения (очень рекомендуется использовать всегда).
*   `-Wextra`: Включить **дополнительные** предупреждения (ещё лучше).
*   `-Werror`: **Считать все предупреждения ошибками**. Полезно для строгой проверки кода.
*   `-g`: Добавить отладочную информацию (для `gdb`).

**5. Оптимизация**
*   `-O0`: Без оптимизации (по умолчанию, удобно для отладки).
*   `-O1`, `-O2`: Базовая и стандартная оптимизация (хороший баланс).
*   `-O3`: Агрессивная оптимизация (максимальная скорость, но может увеличить размер кода).
*   `-Os`: Оптимизация по размеру.

**6. Указание стандарта языка**
*   `-std=c11` (или `-std=c99`, `-std=c17` и т.д.): Указать, какой стандарт C использовать. Это помогает избежать проблем с переносимостью.

### 💡 Практические примеры

```bash
# 1. Простая компиляция (динамическая)
gcc main.c -o app

# 2. Компиляция с предупреждениями и отладкой (хороший стиль)
gcc -Wall -Wextra -g main.c -o app

# 3. Статическая сборка 
gcc -static ofs.c -o ofs

# 4. Компиляция в объектный файл (без линковки)
gcc -c main.c -o main.o

# 5. Указание конкретного стандарта и оптимизации
gcc -std=c17 -O2 main.c -o app
```

Главное правило: **всегда используйте `-Wall -Wextra`**. Это сэкономит вам часы отладки. А для задач, где бинарник должен работать в чужой, потенциально старой системе, используйте `-static`.
